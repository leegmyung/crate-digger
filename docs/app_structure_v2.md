# 앱 정보 구조 v2 — 메뉴·페이지 나눔·팀 페이지 탭·검색 중심 탐색 (2026-11-28)

> **왜:** 사용자 지시 "구조 파악해서 우리 것에도 쓰자" — 색·부품(이미 [디자인 기준서](design_spec_from_chartmetric.md)·[작업 목록](app_rework_plan.md)으로 진행 중)이 아니라 **정보가 어디에 어떻게 나뉘어 있는가**를 경쟁 서비스처럼 바꾼다.
> **근거:** 직접 본 화면 기록 — [Chartmetric 아티스트](research_2026-11-27_chartmetric_artist.md) 1절 · [Chartmetric 공연장](research_2026-11-27_chartmetric_live.md) 1절 · [Viberate 안쪽](research_2026-11-27_viberate_inside.md) 1절.
> **원칙:** 구조의 원리만 가져오고 이름·모양은 우리 말로. 우리가 앞선 것(검증·같은 주최 규칙·한국 공연장)은 **'검증' 메뉴**와 **모든 페이지의 '근거' 줄**로 살린다.
> **화면 용어 (2026-11-28 반영):** 화면에서는 안쪽 용어를 쉬운 말로 통일했다(코드·데이터 칸 이름과 검증 메뉴의 '정답'은 유지, 전체 대조표는 [용어 정리](glossary.md)).

| **아티스트 페이지** | 왼쪽 두 번째 띠에 탭 16개(개요·플랫폼·곡·통계·관객·플레이리스트·…·공연·기능), 개요는 판단→변화→근거→관계 순 | 한 페이지를 길게, 위 탭은 '그 칸으로 이동' 책갈피, 왼쪽 고정 칸에 순위·버튼 | **고정 머리(누구·얼마나 큰가·버튼) + 탭.** 첫 탭(개요)은 요약만, 깊은 근거는 각 탭으로 |

| **차트** | 상위(점수 순) / Trending(7일 변화율 순), 국가·지역·장르별 | 아티스트 차트·추천 차트 13개(Rising on 플랫폼 …) | 차트 = **정의가 고정된 순위표 묶음**(전체·장르·지역·떠오르는·신인), 정의 문장을 표 위에 |
| **공연장·도시·페스티벌** | 위치·공연장·라이브 이벤트 메뉴, 공연장 상세 = 머리 상자 + 출연 팀 표 + 공연 표 + Venue Journey | 페스티벌·도시·공연장 각각 메뉴, 크기·종류 구간 필터 | **장소마다 독립 페이지**(목록 → 상세), 상세는 개요·출연·공연·흐름 |
| **알림 센터** | 리포트 센터: 빠른 알림 6종 + 구독 리포트 + 리포트 빌더 | 팀별 주간 이메일 | 알림은 **한 곳에 모으고**(받은 알림 + 내가 만든 규칙), 각 페이지엔 '이 대상 알림 받기' 버튼만 |
| **목록** | 숏리스트(5종 대상, 권한·공유) · 팔로우 | 내 아티스트·내 차트(저장 필터) | **'내 목록' 하나에** 관심 팀·구독 공연장·저장 필터를 탭으로 |

- 지금 공연장 메뉴 안의 '이번 달·씬 묶음'·'씬 네트워크' 탭은 **공연장 목록의 보기 전환**(표·지도·씬)으로 흡수.

**알림 `#/alerts`**
```
┌ 탭: [받은 알림] [알림 규칙] ──────────────────────────────────────────────┐
│ 받은 알림: 종류별 묶음(새 정답·선정·단계 상승·큰 무대 첫 출연·언급 급증…)  │
```

**내 목록 `#/mine?tab=watch|venues|filters`**: 관심 팀(표|보드, 상태) · 구독 공연장 · 저장한 필터(이름·조건·'발굴에서 열기'·새로 맞는 팀 수).
