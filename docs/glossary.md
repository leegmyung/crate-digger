# 데이터 · 앱 용어 정리

앱과 데이터 문서를 처음 접하는 사람을 위한 정리. 이 프로젝트에서 실제로 쓰는 뜻으로 적었다.
2026-11-28부터 앱 화면에서는 안쪽 용어를 일상어로 바꿔 보여 준다([정리 기준](ux_simplify_2026-11-28.md) 6절 · `docs/app/easy_terms.js`). 코드·데이터 칸 이름과 '검증' 메뉴의 평가 기준('정답')은 그대로 둔다.

## 앱 화면 용어 ↔ 문서·코드 용어

| 화면에 보이는 말 | 예전 말(문서·코드) | 뜻 |
|---|---|---|
| **신호 종류** | 갈래 (`branch`) | 공연 · 선정·지원 · 큐레이션 · 발매 네 종류의 활동 기록 |
| **여러 곳에서 보임** | 여러 갈래 | 공연·선정·매체 등 2가지 이상 신호 종류에서 함께 포착된 단계 |
| **수상·선정** | 정답 · 센 정답 (`outcomes`) | 한대음·헬로루키·CJ 튠업·펜타 슈퍼루키 등 주요 수상·최종 선정 (검증 메뉴에서는 평가 기준 뜻으로 '정답'을 함께 표기) |
| **선정·수상 후보** | 선정·중간 정답 | 주요 신인 프로그램에 선정됐거나 수상 후보에 오른 단계 |
| **언급 전** · **언급 전 신인** | 백지 · 백지 신인 | 첫 발매 뒤 아직 공연·선정·매체 기록이 없는 신인 |
| **신인 소개 매체** | 발굴 매체 (`role: discovery`) | 과거 검증에서 수상·선정 팀을 기준선보다 잘 짚어 후보 점수에 반영하는 매체 |
| **큰 매거진** | 맥락 매체 (`role: context`) | 이미 알려진 팀을 많이 다루는 대형 매거진(참고용, 점수에는 약하게 반영) |
| **공연장 크기 (소·중·대·특대)** | 체급 (`tier: S·M·L·XL`) | 객석 기준 공연장 규모 (~150 · ~400 · ~1,000 · 1,000명+) |
| **같은 주최** | 같은 집안 | 매체와 시상식 주최사가 같아 적중률이 부풀 수 있는 관계 (검증 메뉴에서 분리 집계) |
| **장르 옆 `?`** | 추정 · 추정·약함 (`genre_confidence`) | 프로필·보도 확인 전, 같은 무대 팀·공연장 성향으로 짐작한 장르 |
| **담기** | 관심 추가 · 필터 저장 · 공연장 구독 | 팀·발굴 조건·공연장을 '내 목록'에 모아 두고 알림을 받는 동작 |

## 핵심 비유: 언어 – 문장 – 알아듣는 사람 – 대화창

| 용어 | 비유 | 실제 뜻 |
|---|---|---|
| **SQL** | 언어 (한국어 같은) | 데이터에게 질문하는 표준 언어 |
| **쿼리 (query)** | 그 언어로 쓴 질문 문장 | "선정 프로그램별로 나중에 상 받은 비율"을 SQL로 쓴 한 덩어리 |
| **PostgreSQL · MySQL · BigQuery …** | 그 언어를 알아듣고 답하는 사람 | 데이터를 보관하고 쿼리를 실행하는 프로그램·서비스 |
| **DBeaver** | 대화창 | 쿼리를 입력하고 결과 표를 보는 화면 프로그램 |

프로그램마다 사투리 같은 작은 문법 차이가 있다(날짜 계산 등). 이 프로젝트는 쿼리를 표준에 가깝게 써서 회사의 BigQuery 같은 곳에서도 대부분 그대로 돌아가게 한다. 실행 프로그램은 PostgreSQL.

## 회사의 데이터 보관소 두 종류

| 종류 | 비유 | 하는 일 | 예 |
|---|---|---|---|
| 서비스 DB | 계산대 장부 | 앱이 지금 돌아가는 데 쓰는 데이터(회원·결제). 빠른 기록 | PostgreSQL, MySQL |
| 데이터 창고 (웨어하우스) | 본사 대형 창고 | 몇 년치 기록을 모아 분석용으로 크게 계산 | BigQuery, Redshift, Snowflake |
| 분산 처리 엔진 | 여러 명이 나눠 계산 | 아주 큰 데이터를 컴퓨터 여러 대가 나눠 처리 | Spark, Trino |

- **데이터 분석가**: 질문에 쿼리로 답하고 보고서·대시보드를 만든다.
- **데이터 엔지니어**: 데이터가 매일 쌓이고 흐르는 길(파이프라인)을 만든다.
- 음원 서비스의 청취 기록처럼 큰 데이터는 창고·Spark에서 SQL로 분석한다. SQL 언어는 같아서 PostgreSQL로 익힌 쿼리 실력이 그대로 통한다.

## 이 프로젝트에 나오는 용어

| 용어 | 쉬운 뜻 | 이 프로젝트에서 |
|---|---|---|
| 테이블 / 행 / 열 | 엑셀 시트 / 한 줄 / 한 칸 | 공연 표 한 줄 = 공연 1건 × 출연 팀 1팀 |
| 스키마 | 표들을 담는 폴더 | `raw` 원본, `ref` 규칙표, `core` 기초 뷰 |
| 뷰 (view) | 자주 쓰는 쿼리에 이름을 붙여 저장한 것 | `core.v_signal` = 네 가지 신호 종류(예전 말: 갈래)를 한 표로 |
| 적재 (load) | CSV를 데이터베이스에 옮겨 담기 | `scripts/load_pg.py` |
| 파이프라인 / ETL | 수집 → 정리 → 저장이 자동으로 이어지는 흐름 | 매일 21시 자동 실행 |
| 메타데이터 | 데이터에 대한 설명 정보 | 앨범의 발매일·유통사·장르 |
| 정규화 / 아티스트 매칭 | 표기를 통일해 같은 대상끼리 묶기 | '스트레인지 프룻' = '스트레인지프룻' |
| 데이터 검증 (QA) | 잘못 들어간 데이터 찾기 | 플랫폼마다 다른 발매일, 가격이 이름으로 들어간 행 |
| CTE (`WITH`) | 쿼리 안에서 중간 결과에 이름 붙이기 | 긴 분석을 단계별로 읽기 쉽게 |
| 윈도 함수 | 줄을 합치지 않고 순위·누적·이전 값 비교 | "전날보다 수집량이 50% 줄었나" |
| 대시보드 / BI 도구 | 숫자를 그래프 화면으로 | 진행판, Tableau |
| 지표 / KPI | 성과를 재는 숫자 | 적중률, 선행 기간 |
| 백테스트 | 과거 데이터로 규칙 시험 | 2025~26 수상·선정(정답) 팀 거꾸로 따라가기 |
| 기준선 (baseline) | 아무렇게나 골랐을 때의 성적 | 우리 규칙이 이걸 넘어야 의미가 있다 |
| 적중률 / 재현율 | 고른 것 중 맞은 비율 / 수상·선정(정답) 중 찾아낸 비율 | 신호별 적중률 |
| 선행 기간 | 얼마나 먼저 찾았나 | 수상·선정(정답)보다 몇 개월·몇 년 먼저 |
| A/B 테스트 | 두 버전을 나눠 보여주고 효과 비교 | 서비스 적용 기획에서 다룰 내용 |
