# 인스타그램 수집 점검 (2026-11-27)

> 인스타그램 매거진·공연장·아티스트 계정 499개를 단계별 일정으로 도는 수집(`scripts/collect_insta.py`, `config/insta_accounts.json`)이 계획대로 돌았는지 점검했다.
> 공개 문서라 계정 이름은 쓰지 않고 숫자와 계정 종류만 적는다.

모의 실행(오늘부터 14일, 매일 끝까지 돈다고 가정): 하루 230~240개를 보고 주기를 넘겨 밀리는 계정은 0개다. 계획 자체는 상한 안에 들어온다.
계정당 10~20초라 **매일 40~80분**이 걸린다(매일 실행에서 가장 긴 단계가 됨).

## 2. 실제로 돈 것 (2026-11-27 21시 실행 전 기준)

| 항목 | 값 |
|---|---|
| 한 번이라도 읽은 계정 | **16 / 499** (매거진 12·공연장 보조 4, 모두 2026-11-26) |
| 한 번도 읽지 않은 계정 | **483** — 공연장 345 전부, 매거진 138 |
| 원본 파일 | 2026-11-26 하루치 1개, 121행(계정 13곳) |
| 랩 데이터 신호 | 85행 · 79팀 (큐레이션 72행, 공연 13행) |

**원인**
1. 2026-11-26 21시 실행에서 수집기가 aside 결과(JSON)가 잘린 계정 하나 때문에 **통째로 멈췄다**(`JSONDecodeError`). 이 오류는 이후 코드에서 계정 하나의 실패로 처리되도록 이미 바뀌어 있다(`parse_repl_output`이 `RuntimeError`로 바꿔 넘김 → 계정 단위 `except`).
2. 그런데 수집기는 **상태(`insta_state.json`)와 행을 실행이 끝날 때 한 번만 저장**했다. 그래서 멈춘 날에 본 계정·게시물이 모두 사라졌고, 그 전에 손으로 돌린 16개만 남았다. 499개 계정 일정은 매일 실행에서 아직 한 번도 끝까지 돈 적이 없다.

**고친 것 (`collect_insta.py`, 테스트 추가)**: 계정 **20개마다** 행 파일과 상태를 저장하고, 실행이 끝나든 도중에 멈추든 마지막에 한 번 더 저장한다(`try/finally`). 멜론 수집기(20팀마다 저장)와 같은 방식이다.
같은 날 두 번째 저장부터는 시각이 붙은 새 파일이 생긴다(원본은 고치지 않는다는 규칙).
