# 대시보드 구조 조사 (2026-11-27)

목적: 잘 만든 공개 분석 대시보드들이 **화면을 어떤 순서로 나누는지(파티션 구조)**, **질문마다 어떤 차트를 쓰는지**를 보고, 우리 대시보드(`docs/dashboard.html`)의 섹션 배치를 다시 짠다.

조사 방법: Aside 브라우저(`aside repl`)로 직접 열어 본문 글자와 화면 캡처를 확인했다.
- 확인 못 한 곳: Amplitude·Mixpanel 문서는 Aside 콘텐츠 필터가 막았다 → 같은 종류인 PostHog 문서로 대신 봤다. Tableau "NYC Road Safety"는 12초 안에 다 뜨지 않았다. Chartmetric·Soundcharts·Spotify Wrapped·Kaggle은 시간 관계로 열지 않았다(아래에 넣지 않음).

### ① Tableau Public — Bike Share System Overview (오늘의 비주얼리제이션)
- 링크: https://public.tableau.com/app/profile/bigxpt/viz/CLAUDEDASHBOARD/BIKESHARE
- 보는 사람: 자전거 대여 운영자 (한 화면 운영 요약)
- 섹션 순서: **제목 + 범위 한 줄**("26 stations · 627 docks · Oct 2024 – Oct 2026") → **숫자 카드 5개**(1년 이용 432K, 가장 바쁜 날, 출근 시간 비중 19%, 빈 거치대 횟수…) → **일별 추세 선**(얇은 선=매일, 굵은 선=7일 평균, 최고점에 말풍선) → 시간대별 이용 → 지도형 점(역별 출발량) → **양쪽으로 갈라지는 막대**(역별 "도착-출발" 순증감)
- 질문별 차트: "얼마나 많이?"=숫자 카드 / "언제 늘었나?"=선 + 이동평균 / "어디가 문제?"=정렬된 막대
- 눈여겨볼 점: 카드마다 **숫자 아래 맥락 한 줄**("Peak at 8:00, 142 an hour", "In the last 1Y"). 차트 제목 아래 **부제로 기준을 명시**("Typical weekday, 6 to 9 am, July to October 2026"). 숫자를 강조할 카드만 다른 색(주황)으로 표시.
- 불확실성: 직접 표시는 없고, 매일 값의 흔들림을 얇은 선으로 남겨 평균과 같이 보여 준다.

### ⑤ Kworb — 아티스트별 Spotify 차트 기록 (음악 데이터)
- 링크: https://kworb.net/spotify/artist/3HqSLMAZ3g3d5poNaI7GOU.html (예: IU), https://kworb.net/spotify/country/kr_weekly.html
- 보는 사람: 음악 팬, 업계 사람 (빠른 조회)

- 눈여겨볼 점: **표 위에 측정 한계를 한 줄로 경고**("Total streams here only cover the time spent in each top 200"). "--"로 데이터 없음을 명시. 변동은 +/− 기호만으로 충분히 읽힌다.

### ⑥ Our World in Data — Grapher (예: 기대수명)
- 링크: https://ourworldindata.org/grapher/life-expectancy
- 보는 사람: 일반 대중, 기자
- 구조: 제목 → **정의 한 문장**(지표가 정확히 무엇인지) → 표/지도/선/막대 **탭 전환** → 그림 → **출처 줄**("Data source: …") → 내려받기·공유 → 국가 선택 목록(검색, 정렬, 종류 필터)

- 우리에게: 각 섹션 제목 밑에 "적중률 = …" 같은 정의 한 줄, 아래에 "출처·기준일·표본 n" 한 줄.

### ⑦ PostHog — 퍼널(Funnels) 문서 (Amplitude·Mixpanel과 같은 제품 분석 도구)
- 링크: https://posthog.com/docs/product-analytics/funnels
- 구조(문서에서 확인): 단계 정의 → 단계별 전환·이탈 막대 → "성공/실패한 사람이 누구인가" → **단계 사이 걸린 시간** → 기간별 전환률 추세(바꾼 뒤 좋아졌나, 계절 영향)
- 눈여겨볼 점: 퍼널은 **"단계는 행동이지 필터가 아니다"**, 단계 순서 규칙(순서대로/바로 다음/순서 무관)을 명시해야 한다.
- 우리에게: "중간 정답 → 최종 정답" 퍼널에 **순서 규칙(중간이 최종보다 먼저였나)**과 **두 단계 사이 걸린 시간**을 같이 둔다.

### ⑧ PostHog — 리텐션(Retention) 문서
- 링크: https://posthog.com/docs/product-analytics/retention
- 구조(문서에서 확인): **시작 사건 + 돌아온 사건**으로 묶음(코호트)을 정의 → 기간별 표(묶음 × 경과 기간 = 계단 모양 히트맵) → 속성 필터
- "첫 번째만 / 처음 있었던 때만 / 매번" 세는 방식을 고르게 함 → 정의가 결과를 바꾼다는 걸 화면에 드러낸다.
- 우리에게: "첫 신호가 잡힌 해" 묶음 × "몇 년 뒤 정답을 받았나" 계단 표 = 코호트 히트맵. 단, 지금 데이터 양이면 칸이 너무 비어서 **나중 과제**.

## 2. 공통 패턴 정리

| 패턴 | 어디서 봤나 | 우리 적용 |
|---|---|---|
| 맨 위 "범위 한 줄"(무엇을, 언제부터 언제까지, 몇 개) | ①③⑥ | 제목 밑에 "후보 n명 · 소스 n개 · 2023-01~2026-11 · 기준일" |
| 숫자 카드 + 비교값(▲▼) + 맥락 한 줄 | ①②③ | 카드마다 기준율·지난달 대비 |
| 추세는 이동평균 + 원값 같이, 사건은 세로선 | ①③ | 월별 수집량에 소스 추가 시점 표시 |
| 분포는 평균 대신 히스토그램 | ④ | 리드타임, 연차 |
| 순위는 정렬된 가로 막대, 기준선 겹치기 | ①②④ | 신호별 적중률 vs 기준율 |
| 상세는 정렬 가능한 표, 측정 한계 경고 한 줄 | ③⑤ | 후보 목록, 품질 점검 |
| 정의 → 그림 → 출처/표본 3단 | ⑥④ | 모든 섹션 공통 틀 |
| 퍼널은 단계 순서 규칙 + 단계 사이 시간 | ⑦⑨ | 중간→최종 정답 |

**불확실성/표본 크기를 보여 준 방식**: 대부분의 업무 대시보드(①②⑨)는 아예 안 보여 준다. 잘 하는 곳은 ④처럼 설명에 n을 적거나, ⑤처럼 측정 한계를 경고하거나, ①③처럼 원값 흔들림을 남긴다. 우리는 표본이 작아서(정답 수십 명 수준) **비율마다 n을 같이 쓰고, 막대에 오차 막대(신뢰구간)를 그리고, n이 너무 작으면 흐리게** 하는 것이 꼭 필요하다 — 남들보다 한 단계 더 해야 하는 부분.

## 3. 우리 대시보드 섹션 배치 제안

전체 흐름: **요약 → 결과물(후보) → 근거(신호가 맞나) → 근거 상세(퍼널·시간) → 재료(수집) → 신뢰도(품질·방법)**.
지금 8개 섹션과 내용은 거의 같고, **순서와 각 섹션의 틀**을 바꾸는 제안이다.

공통 틀(모든 섹션): `제목(질문 형태)` → `정의 한 줄` → `차트` → `한 줄 결론(데이터로 채움)` → `출처 · 기준일 · n`.

맨 위 공통 필터 2개만: **갈래(발매/공연/선정·지원/큐레이션, 복수 선택)**, **기간(연도 범위)**. 섹션별 필터는 아래 표에. (필터는 `<select>` + 미리 만든 JSON 다시 그리기로 충분.)

| # | 섹션 | 답하는 질문 | 차트 | 주요 필터 | 한 줄 결론 틀 |
|---|---|---|---|---|---|
| 0 | 헤더 + 숫자 카드 4개 | 지금 상태가 어떤가? | 숫자 카드(카드마다 비교값) — 후보 수(지난주 대비), 최고 lift 신호, 중간→최종 전환률, 리드타임 중앙값 | 공통 필터 | "후보 **N명**(+n), 가장 잘 맞는 신호는 **X**(기준의 **k배**)" |
| 1 | 지금 주목할 후보 | 누구를 봐야 하나? | **표**(Kworb식): 이름, 갈래 수(2+), 갈래 아이콘, 첫 신호일, 최근 신호, 신인 여부, 데뷔 연차. 열 클릭 정렬 | 갈래 수 ≥2/≥3, 신인만, 갈래 | "2갈래 이상 **N명** 중 신인 **M명**, 이번 달 새로 들어온 **k명**" |
| 2 | 어떤 신호가 맞나 (lift) | 이 신호를 받은 팀은 정말 더 자주 정답을 받나? | **가로 막대**: 신호별 적중률, 막대에 **오차 막대**, **기준율 세로선**(②방식), 막대 끝에 "k/n". n<10은 흐리게. 정렬 = lift 순 | 정답 기준(중간/최종), 갈래 | "**X** 신호는 적중률 **a%**로 기준(**b%**)의 **k배**, 단 n=**m**" |
| 3 | 중간 정답 → 최종 정답 | 중간 단계를 받은 팀이 최종까지 가나? | **퍼널 막대**(가로, 2~3단계, 단계별 %와 이탈 수) + 옆에 **단계 사이 걸린 개월 수 작은 히스토그램** | 중간 정답 종류, 기간 | "중간 정답 **N팀** 중 **k팀(p%)**이 최종, 평균 **m개월** 뒤" |
| 4 | 얼마나 일찍 알아챘나 (리드타임) | 첫 신호는 첫 수상보다 몇 개월 먼저 잡혔나? | **히스토그램**(6개월 구간), 중앙값 세로선. 0보다 왼쪽(수상 뒤 신호)은 다른 색 | 신호 갈래, 정답 종류 | "절반은 수상 **m개월 전**에 잡혔고, **p%**는 1년 이상 앞섰다" |
| 5 | 수상할 때 몇 년 차였나 | 정답은 데뷔 몇 년 차에 오나? (=언제까지가 "신인" 구간인가) | **히스토그램/세로 막대**(연차 1,2,3…) + 누적 % 선(선택) | 정답 종류 | "수상자의 **p%**가 데뷔 **k년 차 이내**" |
| 6 | 수집 현황 | 재료가 고르게 쌓이고 있나? | **쌓은 막대(월 × 갈래)** + 소스 추가 시점 세로선(③방식). 그 아래 **소스별 건수 가로 막대** | 갈래, 소스 | "이번 달 **N건**, **X** 갈래가 **p%**로 치우침" |
| 7 | 공연 많은 공연장 | 신인이 어디서 많이 서나? | **가로 막대** 상위 15 (공연 수), 옆 칸에 "그중 후보 수" | 기간(2025~ 기본), 지역 | "상위 3곳이 공연의 **p%**, 후보가 가장 많이 선 곳은 **X**" |

### 순서를 이렇게 바꾼 이유
- 지금은 "후보 → 신호 → 퍼널 → 연차 → 수집 → 월별 공연 → 공연장 → 품질"이다. **리드타임(4)이 없고**, "월별 공연 기록"은 수집 현황의 한 갈래라서 6에 합쳤다(갈래 필터로 공연만 보면 같다).
- 리드타임(4)과 연차(5)를 붙인 이유: 둘 다 "**언제** 알아챌 수 있나"에 대한 답이라 같이 읽힌다.
- 품질(8)과 방법(9)을 맨 아래에: 모든 사례가 출처·정의를 아래 또는 그림 바로 밑에 둔다. 다만 **품질 결과 요약 한 줄은 헤더(0)에도** 넣어 처음부터 신뢰도가 보이게 한다.

### 구현 메모 (정적 HTML 한 장)
- Chart.js(CDN 하나)로 다 된다: 막대(가로 `indexAxis:'y'`), 쌓은 막대, 선, 히스토그램(구간 미리 나눈 막대). 오차 막대는 Chart.js 기본에 없으니 **얇은 막대 하나를 겹치거나** 텍스트 "a% (b–c%)"로 대신. 퍼널은 가로 막대 2~3개로 충분.
- 히트맵(코호트, 품질 × 월)은 Chart.js 기본에 없으므로 **표 칸 배경색**으로 그리는 게 가장 간단.
- 데이터는 매일 만드는 JSON 하나(예: `docs/data/dashboard.json`)에 섹션별로 미리 계산해 넣고, 페이지는 읽어서 그리기만. 필터는 미리 나눠 둔 묶음을 바꿔 끼우는 방식(브라우저에서 무거운 계산 안 함).
- "한 줄 결론"은 JSON 숫자로 문장 틀을 채워서 자동 생성.
- 비율은 항상 `p% (k/n)` 형식, n<10이면 회색 + "표본 적음" 표시.
