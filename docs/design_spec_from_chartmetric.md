# 디자인 기준서 초안 — Chartmetric에서 배운 원리를 우리 앱에 (2026-11-27)

> **무엇을 바탕으로:** 2026-11-27 밤 Chartmetric 앱 안쪽을 직접 보고 남긴 기록([research_2026-11-27_chartmetric_artist.md](research_2026-11-27_chartmetric_artist.md))과 그때 찍은 화면 캡처(저장소 밖에만 보관) 3장(대시보드·아티스트 개요·Rising Index). 색 값은 캡처에서 점을 찍어 잰 **대략값**(JPEG 압축 때문에 ±몇 단계 오차)이고, 어두운 모드는 전환 버튼만 보고 화면은 보지 못했습니다.
> **원칙:** 그들의 색·로고·모양을 베끼지 않고 **왜 그렇게 했는지(원리)**만 가져옵니다. 예를 들어 그들의 진한 청록 메뉴·청록 버튼·민트→남색 색 지도는 **쓰지 않습니다**.
> **우리 쪽 현재 상태:** [design_samples.md](research_2026-11-27_design_samples.md) 3장 진단 — 파랑 한 계열 8단계(`--seg-*`), 알약 모양 약 19곳(`border-radius: 999px` 계열 34줄), 그림자 8~10곳, 모서리 4px, 시스템 고딕. 이 문서는 그 진단과 **'시안 B 바탕 + A의 막대' 제안**과 맞물리게 썼습니다. 강조색은 사용자가 아직 고르지 않았으므로 **자리(토큰)만 정하고 기본 후보 하나**를 적습니다.

## 0. 한 장 요약 — 그들에게서 가져올 원리 8가지

1. **바탕은 아주 옅은 회색, 내용은 흰 카드.** 회색 바탕(대략 #f6f5fd) 위에 흰 카드를 올려 '묶음'을 선 없이 구분. 그림자는 거의 없음.
2. **색은 '의미'가 있을 때만.** 버튼·선택 상태는 강조색 하나, 숫자 강도는 **한 계열 색 진하기**(옅음=낮음, 진함=높음), 값 없음은 **회색 'N/A'**. 오름/내림은 초록 화살표+%.
3. **숫자는 '값 + 변화 + 기준' 3층.** 큰 숫자(변화량) → 작은 색 글자(%) → 작은 회색 글자(현재 총량). 기준(동료 중앙값·범위)이 붙는 숫자는 막대 위 점으로.
4. **요약은 막대, 상세는 표.** 상태(단계·모멘텀)는 '양끝 이름이 붙은 가로 막대', 목록은 정렬 가능한 표. 원그래프·도넛은 거의 없음.
5. **말풍선(ⓘ)에 정의를 쓴다.** 제목 옆 작은 ⓘ에 "무엇을, 어느 기간으로, 무엇과 비교해" 한두 문장.
6. **탐색은 3층: 왼쪽 메뉴(어디) · 위 검색(누구) · 화면 안 탭(무엇).** 검색 결과 한 줄에 '크기(순위)'를 붙여 고르기 전에 비교되게.
7. **팀 상세는 '머리 → 요약 카드 → 변화 → 근거 → 관계' 순서.** 위로 갈수록 짧고 판단용, 아래로 갈수록 길고 확인용.
8. **빈 화면은 '할 일'로 채운다.** 비어 있으면 "아직 없음"만 쓰지 않고 다음 행동 카드(팔로우·목록 만들기·알림 만들기)를 보여 줌.

## 1. 색

### 1-1. 관찰 (Chartmetric, 밝은 모드 대략값)

| 역할 | 관찰 | 원리 |
|---|---|---|
| 페이지 바탕 | 아주 옅은 회색(약 #f6f5fd), 검색창도 같은 색 | 바탕과 입력칸을 같은 옅은 회색으로 → 흰 카드가 '내용'임을 표시 |
| 카드 | 흰색, 모서리 둥글게(약 8px), 그림자 거의 없음 | 선·그림자 대신 **바탕 대비**로 묶음 |
| 본문 글자 | 거의 검정(약 #101010) | 회색 글자는 보조 정보에만 |
| 왼쪽 메뉴 | 진한 색 띠 + 흰 아이콘, 선택 항목은 옅은 네모 | 메뉴를 본문과 확실히 분리(※ 우리는 반대로 '흐리게'를 택함, 아래 표) |
| 강조(버튼·선택) | 한 색(청록 계열) | 강조는 **한 색**, 채운 버튼 1종 + 테두리 버튼 1종 |
| 강도(히트맵 1~10) | 옅은 민트(1) → 청록(3~6) → 진한 남색(10), 한 줄 색 범례 '1 ━ 10' | **한 방향 연속 색**(낮음 옅게, 높음 진하게). 범례를 표 위에 한 번만 |
| 값 없음 | 옅은 회색 칸(약 #efefef)에 'N/A' | 빈칸을 0과 구분 |
| 오름/내림 | 초록 '↑ 1.2%', 내림은 빨강 계열 | 방향은 색 + 화살표(색약 대비) |
| 등급 단어 | 탁월함·훌륭함·평균·평균 이하 (글자) | 등급을 색만이 아니라 **글자로** |

### 1-2. 우리 앱: 현재 → 바꿀 것

| 항목 | 현재 (`docs/app/style.css`) | 바꿀 것 | 이유 |
|---|---|---|---|
| 페이지 바탕 | `--bg #ffffff`, 카드 `--surface #f7f7f9` (흰 바탕 위 회색 카드) | **뒤집기**: `--bg` = 옅은 회색(예: #f5f4f1, 살짝 따뜻한 종이색), 카드·표 = `#ffffff` | 흰 카드가 '내용'으로 떠 보이게. 따뜻한 회색은 웹 도구 기본 회색(차가운 청회색)과 다르게 보이려는 선택 |
| 선 | `--line #e0e3e8` (청회색) | 따뜻한 회색 `#e4e1db`, 진한 선 `#c9c4bb` | 청회색 = 'Tailwind 기본' 느낌의 원인 |
| 강조색 | `--accent #1d4ed8` (파랑) | **토큰은 그대로 두고 값만 교체.** 기본 후보: 탄 주황 `#b4501f`(흰 바탕 대비 약 5:1), hover `#963f15`, 옅은 바탕 `#fbeee6`. 사용자가 초록/빨강/파랑 유지 중 고르면 값만 바꿈 | 강조 한 색 원칙. 그들의 청록과 겹치지 않음 |
| 점수 구성 색 `--seg-*` 10개 | 파랑 7단계 + 회색 3단계 | **두 무리로 줄이기**: ① 갈래 4색(공연·큐레이션·선정·발매 — 범주라서 서로 다른 색, 채도 낮게) ② 나머지 세부 항목은 회색 3단계. 파랑 계단 삭제 | 색은 '의미'에만. 같은 색 8단계는 구분이 안 됨 |
| 강도(히트맵·막대 진하기) | 없음(막대는 `--bar-score` 한 색) | **새 토큰 `--ramp-1`~`--ramp-5`**: 강조색 계열 5단계(가장 옅음 = 바탕에 가까움, 5 = 강조색보다 진함). 3까지 글자 검정, 4~5 글자 흰색 | 그들의 '한 방향 연속 색' 원리, 색 자체는 우리 강조색에서 만듦 |
| 값 없음 | 칸을 비우거나 0으로 보임 | **새 토큰 `--na-bg`(#efede9)·`--na-ink`(#8a857c)**, 글자 '자료 없음' 또는 '—' | 0점과 '모름'을 구분 |
| 오름/내림 | `.delta-badge.is-up` 등(초록·빨강 배지, 알약) | 배지 없애고 **글자색+화살표만**: 오름 `#2f7d4f`, 내림 `#b23a32` | 알약 줄이기 + 색약 대비 |
| 정답 등급 S/A/B | `--graph-grade-s` 주황 · `-a` 파랑 · `-b` 회색 (3색) | **한 색 3모양**: S = 강조색 채움, A = 강조색 테두리, B = 회색 테두리. 글자 'S·A·B'는 유지 | 색 수 줄이기, 강조색과 연결 |
| 출처 역할(발굴·맥락·검증 대기·제외) | 초록·노랑 계열 배지 | 글자 꼬리표(네모, 테두리만) + 발굴만 강조색 글자 | 등급을 글자로 |
| 씬 묶음 8색 `--scene-c*` | 파랑·청록·주황·보라·분홍… 8색 | 유지하되 **채도 낮춘 8색**(관계망 그림 전용). 강조색과 같은 색은 빼기 | 그림 안에서만 쓰는 범주색 |
| 어두운 모드 | `--bg #08090a` 거의 검정 + 파랑 `#60a5fa` | 바탕 `#121110`(따뜻한 검정), 카드 `#1b1a18`, 선 `#2c2a27`, 강조 `#f08a4b`(밝힌 주황), 강도 단계는 **반대로**(진할수록 밝게) | 밝은 모드와 같은 원리, 대비 4.5:1 이상 유지(지금 주석의 WCAG 기준 그대로) |

> 색 값은 제안입니다. 바꾸기 전에 글자 대비(4.5:1)를 도구로 다시 재고, 강조색은 사용자 선택을 따릅니다.

## 2. 글꼴·크기 단계

### 2-1. 관찰
- 산세리프 한 종류, 숫자도 같은 글꼴(표에서 오른쪽 정렬). 한국어 화면은 시스템 고딕.
- 크기 단계는 대략 5단: 화면 제목(약 22px) · 카드 제목(약 17~20px, 굵게) · 큰 숫자(카드 안 변화량, 약 20px 굵게) · 본문/표(약 15px) · 보조(약 12~13px, 회색, 범위·날짜·축).
- 숫자 단위를 줄여 씀('40.6만', '1.2천') — 표 폭을 좁게 유지.
- 대문자 영문 소제목(공개 페이지의 'MONTHLY LISTENERS' 같은)은 작은 글씨+자간.

### 2-2. 현재 → 바꿀 것

| 항목 | 현재 | 바꿀 것 |
|---|---|---|
| 본문 글꼴 | `--font-sans` 시스템 고딕(애플 SD 고딕·Pretendard·Noto) | 유지. 단 **Pretendard를 첫 순위**로(설치 안 된 컴퓨터는 그대로 시스템 글꼴) — 기기마다 모양 차이 줄이기 |
| 숫자 | `--font-mono` 고정폭 | 표 숫자는 **본문 글꼴 + `font-variant-numeric: tabular-nums`**(자릿수 맞춤)로 바꾸고, 고정폭은 SQL 화면에만. 고정폭 글꼴은 '개발 도구' 느낌 |
| 크기 단계 | xs 13 · sm 14 · table 14 · base 15.5 · h3 15.5 · lg 17 · xl 20 · h2 18 · h1 22 (9개, h3=base) | **6단으로 정리**: 12(보조) · 14(표·라벨) · 15(본문) · 17(카드 제목) · 20(큰 숫자) · 24(화면 제목). 굵기는 400/600/700 세 가지만 |
| 큰 숫자 | 화면마다 다름(`.kpi-chip-val` 등) | '큰 숫자'는 **한 화면 최대 4개**(요약 카드 안)만 20px 굵게. 나머지 숫자는 표 안 14px |
| 숫자 단위 | `fmtInt`로 전체 자릿수(예: 12,345) | 표에서는 '1.2만'식 줄임 + 마우스 대면 전체 값(title) |
| 작은 영문 대문자 소제목 | 없음 | 쓰지 않음(한국어 화면이라 어색) — 대신 12px 회색 굵은 한글 소제목 |

## 3. 간격·격자·밀도

### 3-1. 관찰
- 화면 폭 전체를 쓰고 바깥 여백 넓음(카드 좌우 약 40px), 카드 사이 약 20~24px.
- 표 한 줄 높이가 넉넉함(대시보드 표 약 60px — 원형 사진 포함), 히트맵 칸은 약 130×40px, 줄 간격 약 65px. **한 화면에 8~10줄** — 훑기보다 '하나씩 보기' 밀도.
- 카드 안 블록은 가로 4칸(요약 카드·타일), 아래로 갈수록 2칸·1칸 넓은 블록.
- 오른쪽 아래 떠 있는 둥근 버튼 2개(질문·도움말).

### 3-2. 현재 → 바꿀 것

| 항목 | 현재 | 바꿀 것 | 이유 |
|---|---|---|---|
| 간격 단계 | 4 · 8 · 12 · 18 · 24 · 28 (18·28이 4의 배수 아님) | **4 · 8 · 12 · 16 · 24 · 32** (4의 배수) | 줄 맞춤이 쉬워짐 |
| 표 밀도 | 칸 안쪽 10px 12px, 줄 높이 약 41px | **두 밀도 전환**: '촘촘'(안쪽 6px, 줄 약 32px — 후보 목록 기본, 한 화면 25줄 이상) / '편하게'(안쪽 12px, 줄 약 44px — 관심 목록·팀 상세) | 우리는 매일 많은 팀을 훑는 도구라 그들보다 촘촘해야 함. 원리는 '화면 목적에 맞춘 밀도' |
| 카드 | 테두리 1px + 일부 그림자, 모서리 4px | **테두리 없음 + 흰 카드 + 바탕 대비**, 모서리 8px(카드)·4px(버튼·입력칸·꼬리표), **그림자 0곳** | 그림자 8~10곳 → 0 |
| 격자 | 화면마다 자유 배치 | 본문 최대 폭 1280px, 12칸 격자. 요약 줄 = 4칸, 근거·표 = 12칸, 곁 정보 = 8+4 | 블록 폭 규칙 통일 |
| 떠 있는 버튼 | 없음 | 만들지 않음 | 우리 화면엔 AI 도우미가 없음 |

## 4. 막대·히트맵·말풍선·꼬리표

### 4-1. 관찰
- **상태 막대(아티스트 개요 맨 위 4칸):** 칸 제목(ⓘ) → 큰 글씨 현재 상태 → 가는 가로 막대(채운 부분 = 현재 위치) → 막대 아래 양끝 작은 글씨(낮은 쪽 이름 ↔ 높은 쪽 이름). 숫자 없이 위치만.
- **동료 비교 막대:** 회색 긴 막대 위에 최소·중앙값·최대 눈금, 내 위치는 진한 점 + 이름표, 옆에 등급 단어.
- **히트맵:** 칸마다 숫자 + 배경 진하기, 칸 사이 흰 틈 약 12px, 모서리 살짝 둥글게. 열 머리 = 아이콘 + 두 줄 이름 + 기간 드롭다운. 값 없으면 회색 'N/A'.
- **변화 타일:** 플랫폼 로고 · 지표 이름 / 큰 변화량 · 색 % / 회색 현재 값 — 3줄.
- **말풍선:** 제목 옆 작은 ⓘ, 정의 문장 + 등급 목록(이름 — 한 줄 설명).
- **꼬리표:** 장르·분위기는 테두리 네모 칩(배너 위에선 흰 테두리), 순위 칩(#171 대한민국)은 옅은 회색 네모.

### 4-2. 현재 → 바꿀 것

| 항목 | 현재 | 바꿀 것 |
|---|---|---|
| 점수 구성 막대 | 한 줄 누적 막대(`--seg-*` 파랑 단계로 조각) | **항목별 한 줄씩 가로 막대**(이름 · 막대 · 값). 막대 색은 강조색 한 색, 길이만 다름. 누적 막대는 '구성 비율'을 볼 때만 회색+강조 2색 |
| 동료 비교(새로 만들 것) | 없음 | **'같은 발굴 단계 N팀 중' 막대**: 회색 긴 막대 + 중앙값 눈금 + 내 위치 점(강조색) + 오른쪽 글자 등급(탁월·좋음·보통·아래). 팀 상세 점수 근거에 사용 |
| 상태 막대(새로 만들 것) | 발굴 단계는 글자 배지(백지·첫 신호·여러 갈래·선정·졸업) | 팀 상세 맨 위 **4칸 상태 막대**: 발굴 단계 · 최근 활동 · 갈래 수 · 씬 연결. 막대 양끝에 단계 이름 |
| 히트맵(새로 만들 것) | 없음 | 후보 목록 '색 지도 보기' 전환: 열 = 신호 6~8개, 칸 = 1~5단계(`--ramp-*`), 값 없음 = `--na-bg`. **칸 사이 2px 틈, 모서리 2px**로 촘촘하게(그들보다 작게), 범례는 표 위 한 줄 |
| 변화 표시 | `.delta-badge`(알약 배지) | 배지 없이 '▲ 3' / '▼ 1' 글자(오름·내림 색). 큰 숫자 + 작은 변화 + 회색 기준 3층은 요약 카드에만 |
| 말풍선 | 일부 칸에 `title` 속성(브라우저 기본 노란 상자) | **공용 ⓘ 말풍선 하나**: 흰 상자 + 1px 선 + 13px 글자, 최대 폭 320px. 내용 형식 고정: ① 무엇 ② 기간 ③ 비교 기준 ④ (등급이면) 구간 목록. 키보드 초점으로도 열림 |
| 알약 배지 | 약 19곳(`border-radius: 999px` 34줄) | **네모 꼬리표(모서리 4px) 하나로 통일**, 채움 없이 테두리만. 강조가 필요한 꼬리표만 강조색 글자. 동그라미는 '개수 점'(메뉴 숫자) 하나만 남김 |
| 그래프(Chart.js 등) | 화면마다 색 다름 | 선 = 강조색 1개 + 비교선 회색, 격자선 아주 옅게, 축 글자 12px 회색, **사건 표시는 그래프 위 작은 숫자 동그라미**(그날 사건 수, 마우스 대면 목록) |

## 6. 팀 상세 블록 순서

### 6-1. 관찰 (아티스트 개요, 위→아래)
머리 띠(사진·이름·순위·국가·성별/그룹·레이블·장르 칩, 오른쪽 위 알림·비교·새로고침·내려받기) → 시작 안내 카드(처음만) → **4칸 상태 막대** → **변화 타일 줄**(7일/30일/전체 전환) → 최근 업적 3장 → 동료 비교 카드 → 지역 → 순위 칩 → 청중 요약 → 최신 발매·앨범·상위 곡 → 업적 목록 → 이상치 문장 → **사건 전후 표** → 공연 → 팬 수 비교 → 뉴스 → 비슷한 아티스트 → 연관 레이블.

## 7. 필터 패널 형태

### 7-1. 관찰
- 표 위 한 줄: '필터' 글자 · **적용 개수 상자(1 >)** · 채운 '+ 필터 추가' 버튼 · 적용된 필터 꼬리표('경력 단계: 2 선택됨 ⓧ') · '지우기' 글자 버튼 · 오른쪽에 그룹화·열 순서 드롭다운.
- '+ 필터 추가'를 누르면 **묶음별 긴 목록**(속성 · 관객 · 지표 · 지표 변화 · 스타일), 항목마다 '아무 ○○' 기본값 + 선택지, 개수 표시(예: 장르 옆 팀 수).
- 저장한 필터를 문장 이름으로 위에 두고 '실행'(예: "최근 2년 내 데뷔한 모멘텀 높은 …").
- 추천 프리셋은 동그란 아이콘 + 두 줄 이름 가로 줄.
- 지표 기간 전환은 작은 분절 버튼(7D · 28D · 60D · 합계 · 변화 · % 변화).

### 7-2. 현재 → 바꿀 것 (`docs/app/views/candidates.js` `.inline-filter-bar` 등)

| 항목 | 현재 | 바꿀 것 |
|---|---|---|
| 필터 줄 | `.inline-filter-bar` + `.inline-more-filters`(더 보기) + 알약 `.filter-chip` | **한 줄 구조 통일**: [필터 n] [+ 필터 추가] [적용된 꼬리표들 ⓧ] [모두 지우기] ……… [기간: 7일·30일·6개월] [보기: 표·색 지도] |
| 필터 추가 | 자주 쓰는 것만 펼침 | 눌렀을 때 **묶음별 목록**: 팀(장르·지역·솔로/그룹) · 단계(발굴 단계·첫 발매 6/12/18/24/36개월) · 신호(갈래·선정 단계·공연장 체급·매체) · 변화(최근 7/30일 새 신호) — 각 항목 옆 **해당 팀 수** |
| 적용된 필터 | 알약 칩 | 네모 꼬리표 '첫 발매: 24개월 이내 ⓧ' |
| 저장 필터 | 없음 | **'이 필터 저장'** → 위 줄에 문장 이름으로 표시('24개월 이내 · 지방 공연 많은 밴드') + 주간 알림 받기 체크(연구 문서 6절 3번) |
| 프리셋 | 없음 | 문장형 프리셋 3~5개를 필터 줄 위에 글자 버튼으로(동그란 아이콘 없이): '갓 데뷔(12개월)' · '백지 신인' · '선정 직후' · '지방 씬' |
| 기간 전환 | 화면마다 다름 | 공용 분절 버튼(네모, 선택 = 강조색 밑줄) |

## 8. 빈 상태 · 불러오는 중 · 자료 없음

### 8-1. 관찰
- **빈 상태:** 숏리스트가 없을 때 큰 설명 한 문장 + 채운 버튼('후보 목록 만들기'). 대시보드는 팔로우한 팀이 없으면 '추천' 표로 채우고, 그 아래 **할 일 카드 4장**(각 '페이지로 가기 / 완료로 표시').
- **자료 없음:** 칸은 회색 'N/A', 블록은 '사용 가능한 데이터 없음'·'해당 아티스트의 upcoming 행사 공연이 없습니다' 같은 한 줄. 연결 안 된 플랫폼은 '0 Followers'로 표시 — **0과 '없음'을 섞는 실수**(우리가 피할 점).
- **불러오는 중:** 직접 관찰은 못 함(캡처에 일부 블록이 늦게 그려지는 모습만).
- **오류:** "이런! 문제가 발생했습니다 … 다시 시도 / 대시보드로 이동 / 지원팀에 문의" — 원인 대신 다음 행동 3개.

### 8-2. 현재 → 바꿀 것

| 상황 | 현재 | 바꿀 것 |
|---|---|---|
| 빈 상태 | `.empty-state`(테두리+회색 상자, 제목+설명) / 팀 상세 "선택된 팀이 없습니다" | 상자 테두리 없애고 **설명 한 문장 + 다음 행동 버튼 1개**(예: 관심 목록 비었음 → '후보 목록에서 고르기'). 첫 방문엔 이번 주 브리핑 위에 **할 일 3장**(관심 팀 추가 · 필터 저장 · 주간 알림 켜기), 완료하면 사라짐 |
| 블록 안 자료 없음 | "기록된 활동 신호가 없습니다." 등 회색 작은 글자(블록마다 문구 제각각) | 형식 통일: '— 아직 기록 없음 (마지막 확인 11/27)'. **수집 안 한 것('모름')과 수집했는데 없는 것('0')을 구분**: 모름 = `--na-*` 회색 '자료 없음', 0 = 숫자 0 |
| 칸 안 자료 없음 | 빈칸 | `—` + 마우스 대면 이유('인스타 계정 연결 안 됨') |
| 불러오는 중 | `renderViewSkeleton`(회색 상자 뼈대) | 유지. 뼈대 상자를 실제 블록 크기·순서(머리 띠 → 4칸 → 표)와 같게, 움직임 줄이기 설정을 켠 사람에겐 반짝임 끄기 |
| 오류 | `setGlobalError` 문장 | 문장 + **다음 행동 2개**('다시 불러오기' · '데이터 수집·품질 화면 보기'), 기술 오류 원문은 접어서 |
| 커버리지 | 없음 | 표 머리 칸 아래 작은 회색 숫자 'n/N팀'(그 칸 값이 있는 팀 수) |

## 9. 적용 순서 제안 (앱 담당에게 넘길 단위)

1. **토큰 정리(작음):** 1-2·2-2·3-2 표의 색·글자·간격 토큰 교체, 그림자 0, 알약 → 네모 꼬리표. 화면 구조는 그대로 → 바뀐 인상 확인 후 강조색 확정.
2. **공용 부품(중간):** ⓘ 말풍선 · 상태 막대 · 동료 비교 막대 · 자료 없음 표시 · 분절 기간 버튼.
3. **팀 상세 재배치(중간):** 6-2 순서 + 쪽 안 목차.
4. **후보 목록 필터 줄 + 색 지도 보기 + 저장 필터(중간~큼):** 7-2. 동료 비교·저장 필터 알림은 데이터 쪽 SQL(백분위·저장 필터 매칭)이 함께 필요.
5. **빈 상태·할 일 카드(작음).**

**피할 것(상표·고유 디자인):** 진한 청록 왼쪽 띠, 민트→남색 색 지도, 동그란 프리셋 아이콘 줄, 흐린 사진 배너, 떠 있는 질문 버튼, 그들의 화면 이름(예: 'Career Snapshot', 'Rising Index')을 우리 화면 문구로 쓰기. 우리 화면 이름은 우리 말(상태 막대·색 지도·사건 기록)로.
