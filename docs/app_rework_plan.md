# 앱 다시 만들기 작업 목록 (2026-11-27) — 안티그래비티에게 넘길 것

> **근거 문서:** [디자인 기준서](design_spec_from_chartmetric.md)(9절 적용 순서) + 경쟁 서비스 안쪽 조사 3개의 '바로 만들 것' — [Chartmetric 아티스트](research_2026-11-27_chartmetric_artist.md) 0·6절, [Viberate 안쪽](research_2026-11-27_viberate_inside.md) 6절, [Chartmetric 공연장](research_2026-11-27_chartmetric_live.md) 6절.
> **규칙:** 한 작업 = 안티그래비티 한 번. **큰 파일은 통째로 열지 않고 적힌 줄 범위·선택자만** 고친다(`style.css` 6,169줄, `db.js` 2,538줄, `graph.js` 2,571줄, `candidates.js` 1,276줄). 줄 번호는 2026-11-27 기준이라 조금 밀렸을 수 있으니 절 제목 주석(`/* ---------- … */`)으로 찾는다. 새 부품은 새 파일로 만들고 기존 파일엔 불러오기 몇 줄만 더한다. 데이터 계산은 앱이 아니라 `scripts/`·`docs/lab/sql/` 쪽이 맡고, 앱은 읽어서 그리기만 한다.
> **강조색:** **사용자 선택 대기 — 기본은 탄 주황.** `style.css` 맨 위 `--accent` 한 줄(어두운 모드는 `[data-theme="dark"]`의 `--accent` 한 줄)만 바꾸면 버튼·선택 표시·막대·색 지도(`--ramp-*`)가 모두 따라 바뀌어야 한다. 다른 곳에 색 값을 직접 쓰지 않는다.

## 공통 완료 기준 (모든 작업에 적용)

- **화이트(밝은 모드)·블랙(어두운 모드)** 둘 다 열어 글자가 잘 읽히는지(대비 4.5:1 이상) 확인. 바꾼 화면 캡처 2장(밝게·어둡게)을 보고에 첨부.
- **모바일 375px 폭**에서 가로로 넘치지 않고, 누르는 곳은 44px 이상.
- 브라우저 콘솔 오류 0. 앱이 읽는 데이터 형식을 건드린 경우 `python3 -m unittest discover -s tests` 통과.
- 색 값은 `var(--토큰)`으로만. 새 `box-shadow`, 새 `border-radius: 999px` 금지(개수 점 제외).
- 데이터가 없을 때 화면이 깨지지 않고 '자료 없음'(회색) 또는 '아직 기록 없음'으로 나옴 — 0과 '모름'을 구분.

**크기:** S = 1~2시간(파일 1~2개, 한 군데) · M = 반나절(파일 2~3개) · L = 하루(새 부품 + 화면 배치). L은 가능하면 둘로 쪼갠다.
**데이터 상태:** ✅ 지금 있음 · ⏳ 스크립트는 있고 결과 파일이 곧 생김 · 🆕 아직 없음(데이터 쪽 작업 먼저 — 맨 아래 표).
