# 후보 점검 — 인디 신인 발굴 대상이 아닌 후보 찾기 (2026-11-27)

정답에서 기획사 아이돌을 뺀 뒤, **후보 쪽**에도 같은 잡음이 있는지 점검했습니다. 대상은 오늘 기준 점수 v2 후보 상위 300팀(`docs/lab/sql/candidates.sql`)입니다. **규칙은 적용하지 않았고 제안만** 합니다.

- 만들기: `.venv/bin/python scripts/candidate_audit.py` → 팀별 근거는 비공개 파일(`data/raw/review/candidate_audit_<날짜>.csv`)에, 이 문서에는 건수·대표 사례·제안만.
- 근거는 모두 저장소 데이터: 팀 표의 소속사, 멜론 검색 결과(등록 번호·팬 수·장르), 공개 기사 제목('정규 N집'), 아티스트 연결표의 별칭·플랫폼 번호, 공연 기록.

### (b)를 어떻게 판정했나 — 멜론 등록 번호

멜론 아티스트 번호는 등록 순서대로 커집니다. 이미 받은 멜론 프로필 308개로 번호와 실제 첫 발매 연도를 견줘 보니:

| 멜론 번호 | 프로필 수 | 첫 발매 연도 중앙값 | 2019년 이전 비율 |
|---|---|---|---|
| 50만 미만 | 31 | 2003 | 100% |
| 50만~100만 | 42 | 2014 | 98% |
| 100만~250만 | 33 | 2017~2018 | 83~100% |
| 250만~300만 | 59 | 2021 | 5% |
| 300만 이상 | 113 | 2022~2024 | 1~3% |

그래서 **번호 250만 미만**이면 '첫 발매 3년 이내'(신인 기준)를 넘었을 가능성이 높다고 봤습니다. 다만 근거가 **멜론 번호가 있는 108팀에만** 있어서, 23건은 최소치입니다(나머지 192팀은 근거 없음 = 판단 보류).

## 적용한 것 (2026-11-27)

- **규칙 7 (버그 수정)** — 검색 결과 링크에서 `goArtistDetail('번호')` 안의 숫자만 읽고, 1,000 미만 번호는 버립니다(`collect_artists.py`). 연결표(`artist_xref.py`)도 1,000 미만 멜론 번호는 쓰지 않습니다. 전체를 다시 보니 같은 버그로 잘못 맞춰진 이름이 상위 300팀 밖까지 **17개**(W24·GR2N!·64ksana 등) 있어 모두 '다시 검색'으로 돌렸고, 잘못된 번호로 받은 엉뚱한 가수 프로필 8행은 지우지 않고 연결에서만 뺐습니다. 실제 번호가 1,000 미만인 오래된 가수(예: 강산에)도 함께 빠지지만, 신인 후보가 아니라 영향이 없습니다.
- **규칙 1 (명단 우선순위)** — 멜론 보강 명단 맨 앞(0순위)에 최신 후보 점검의 (b) 팀을 순위 순으로 둡니다. (b) 팀은 대부분 멜론 번호는 이미 있고 프로필만 밀려 있어서(받을 프로필 187개, 하루 상한 100개), 수집기가 **명단 순서대로 프로필을 먼저** 받게 했습니다. 매일 21시 실행부터 반영됩니다.

**권장 순서:** 7(버그 수정) → 1(데이터로 해결) → 4(사람 확인분 기록). 2·3은 프로필 수집이 늦어질 때의 보조 수단으로, 백테스트에서 효과를 먼저 확인한 뒤 결정하는 것을 제안합니다.

## 적용한 것 (코디네이터, 2026-11-27 사용자 결정 뒤)

- **후보 제외 목록**: `config/source_roles.json`의 `candidate_rules.excluded_teams`(팀 → 이유). 여기 적힌 팀은 랩 데이터 팀 표에서 빠져 후보 목록·백테스트에 들어가지 않는다. 처음 넣은 팀: 팻햄스터캉뉴(두 팀 합동 표기), 더더·모임 별·딕펑스·검엑스·생각의여름(2015년 이전 데뷔한 기성 팀).
