실효성 검증 설계

검증은 두 가지로 합니다. 하나는 지표 성장(얼마나 컸나), 다른 하나는 공증 결과(나중에 공인 프로그램이 같은 아티스트를 골랐나)입니다. 우리가 먼저 찾은 아티스트가 나중에 헬로루키나 OPCD에 선정되면, 그게 대시보드가 맞았다는 가장 알기 쉬운 증거가 됩니다.

선정 그룹

비교 그룹

신규성(첫 발매 1년 이내) + 차트 진입·상승 + 평론 신호 + 아직 작은 규모(YouTube 구독자 기준)
공증 결과
Pitchfork Best New Music 등 주요 매체 선정, 주요 페스티벌 라인업, 레이블 계약

국내 · 인디 신보

질문
내가 먼저 고른 신인이 나중에 헬로루키·OPCD 같은 공인 프로그램에 선정되는가, 몇 달 먼저 찾았는가
선정 그룹
인디 신보 풀에서 발굴 점수 상위
비교 그룹
같은 시기 같은 풀에서 선정되지 않은 신보 무작위 추출
발굴 점수
평론·큐레이션 언급(킨디라운지, 웹진) + 초기 반응 속도 + 아직 작은 규모
공증 결과
헬로루키, OPCD, 원 콘쿨, 한국대중음악상 후보, 주요 페스티벌 라인업
적중률선정 그룹 중 기간 내 공증 결과가 나온 비율. 비교 그룹보다 높아야 의미가 있음
선행 기간우리가 선정한 날부터 공증 발표일까지 며칠 먼저 찾았나 (중앙값)
재현율공증 프로그램 선정자 중 우리가 미리 찾아둔 비율. 놓친 아티스트는 왜 놓쳤는지 분석
T0선정일. 모든 지표 기준값
T+14단기. 초기 반응 속도
T+90중기. 성장 지속 여부, 신규 입점
T+180~365장기. 규모 변화, 레이블·공연
성과 지표T0 대비 YouTube 조회수·구독자 증가 배수, 새로 입점한 플랫폼 수, 차트 재진입
성공 기준은 먼저 정하기예: 선정 그룹의 90일 조회수 증가 중앙값이 비교 그룹의 1.5배 이상
소급 불가과거 지표는 나중에 구할 수 없어 오늘부터 매일 쌓아야 함

정해야 할 것 · 위험

높음Bandcamp 약관

Acceptable Use 정책이 스크래핑을 금지한다는 보도가 있음. 원문 확인 후 공개 차트만, 하루 1회, 소량으로 범위를 정하고 원본은 공개하지 않기.

높음수집 시작 시점

장기 검증은 오늘부터 쌓인 기록으로만 가능. 분석보다 수집기를 먼저 돌려야 함.

높음발굴 점수 · 성공 기준

추적을 시작하기 전에 문서로 고정. 결과를 본 뒤 바꾸면 검증이 무의미해짐.

높음후보와 정답 분리

공증 프로그램 선정 목록을 후보 수집이나 발굴 점수에 쓰면 정답을 보고 맞히는 셈. 선정 시점에 이미 발표된 결과는 점수에서 빼고, 선정일 이후 발표만 적중으로 셈.

중간공증 프로그램 목록

헬로루키, OPCD, 원 콘쿨, 한국대중음악상, 페스티벌별 발표 주기와 과거 회차 자료를 정리. 과거 선정자는 백테스트용으로도 쓸 수 있음.

중간아티스트 매칭

동명이인, 한/영 표기, 공식 채널과 팬 업로드 구분. 신뢰도와 수동 검수로 관리하고, 품질 지표로 보여주기.

중간국내 스트리밍 크롤링

멜론·벅스는 공개 API가 없음. 비교 그룹용 소량 수집도 약관 확인 필요. 대안은 MusicBrainz의 한국 발매.

중간Tableau 연결

Tableau Public은 DB 직접 연결 불가 → CSV·Google Sheets 내보내기. DB 직접 연결은 Desktop (학생 라이선스 확인).
