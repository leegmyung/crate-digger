# 사진·바로 듣기 커버리지 (2026-11-28)

Chartmetric처럼 팀마다 **사진**과 **바로 재생**을 붙이기 위한 데이터 규칙. 앱 화면 연결은 UI 작업(`docs/app/player_pick.js`, `docs/app/db.js`)이 맡고, 여기는 데이터 쪽 규칙만 적는다.

## 대상 팀

`scripts/coverage_targets.py` — 오늘 점수(브라우저와 같은 `docs/lab/sql/candidates.sql`) 상위 500팀 → 그 밖의 정답 팀 순서.
`data/raw/state/coverage_targets.json`(비공개)에 저장하고, 하루 한도가 있는 수집기(스포티파이 검색·사진, MusicBrainz, 유튜브 채널)가 이 순서대로 먼저 처리한다. 같은 스크립트가 상위 300·500·정답 팀의 사진·바로 듣기 비율을 출력한다.

## 바로 듣기 — `docs/lab/data/players.csv`

팀마다 최대 2줄 (`scripts/players.py`, `export_lab_data.py`가 만든다).

| 칸 | 뜻 |
|---|---|
| `team_key` | 팀 키 |
| `kind` | `spotify`(아티스트 삽입 재생) / `youtube`(영상 삽입 재생) |
| `id` | spotify: `artist:<22자>` (player_pick.js `parseSpotifyRef`가 아티스트로 읽음) · youtube: 영상 번호 11자 |
| `title` | 영상 제목 (spotify는 빈칸) |
| `channel_title` | 영상을 올린 채널 (spotify는 빈칸) |
| `source` | 고른 근거: `spotify` / `official`(팀 공식 채널) / `stage`(무대 채널) / `search`(검색) |
| `published_at` | 영상 올린 날 `YYYY-MM-DD` (spotify는 빈칸) |
| `view_count` | 가장 최근 조회수 (`raw_video_stats`, 모르면 빈칸) |

**유튜브 대표 영상 고르는 순서** — 눌렀을 때 그 팀 음악이 나올 가능성이 높은 것부터:
1. 공식 채널 라이브(`official_live`), 최신
2. 공식 채널 음악 영상(제목에 MV·Official Audio·Lyric·Live 등), 최신
3. 무대 채널 영상(`stage`), 조회수 많은 것 → 같으면 최신
4. 공식 채널 그 밖의 영상(브이로그 등), 최신
5. 검색으로 찾은 영상(`search`), 조회수 → 최신

후보 영상은 `videos.csv`와 같은 걸러내기(이름 맞추기·인터뷰/쇼츠 제외)를 거친 **전체** 목록이다(`videos.csv`처럼 팀당 6개로 자르기 전).

## 사진 — `docs/lab/data/images.csv`

팀마다 1장: **스포티파이 아티스트 사진 → 없으면 유튜브 공식 채널 아바타**. 칸 `team_key, url, source, page_url`.
`page_url`은 출처 페이지(스포티파이 아티스트·유튜브 채널) — 사진 옆에 출처 링크를 걸 때 쓴다.
허용 주소: `i.scdn.co`, `yt3.ggpht.com`, `yt3.googleusercontent.com`의 https만 (앱 `db.js IMAGE_URL_RE`와 같음).

## 링크를 어디서 얻나

| 출처 | 얻는 것 | 비용·규칙 |
|---|---|---|
| 스포티파이 검색 (`collect_spotify.py`) | 아티스트 번호 + 검색 결과의 사진 | 하루 예산 공유(`spotify_budget.py`), 429면 그날 쉼 — 우회 안 함 |
| 스포티파이 사진 (`collect_artist_images.py`) | 사진 | 검색 때 받은 사진이 있으면 요청 안 함 |
| MusicBrainz (`collect_musicbrainz.py`) | 공식 유튜브 채널·스포티파이 번호·인스타 | 공개 API(robots 허용, 핵심 데이터 CC0), 2초 간격. 이름 키가 같은 한국 아티스트가 **딱 하나**일 때만, 짧은 이름·흔한 낱말은 안 물음 |
| 유튜브 공식 채널 (`collect_yt_channels.py`) | 채널 아바타·최신 영상 10개 | channels.list·playlistItems 각 1단위. search.list(100단위) 안 씀. 채널 주소는 links.csv·MusicBrainz·인스타 소개란에서만 |

**안 쓰는 방법과 이유**
- **유튜브 핸들 추측**(팀 이름으로 `@이름` 찾기): 2026-11-28 시험에서 공식 채널을 이미 아는 120팀에 해 봤더니 결과가 나온 59팀 중 **같은 채널 4팀, 같은 이름의 남의 채널 55팀** → 쓰지 않는다.
- **멜론 프로필 사진**: 아래 판단.

## 멜론 프로필 사진을 앱에 걸어도 되나 — 판단: 쓰지 않는다 (구현 안 함)

1. **주소를 얻는 단계부터 막힘**: `www.melon.com/robots.txt`는 일반 로봇(`User-agent: *`)에 `/global-k-chart`만 허용하고 나머지 전체(`Disallow: /`)를 막는다. 사진 주소는 아티스트 페이지에서만 나오므로, 주소를 모으려면 막힌 페이지를 읽어야 한다. (`/artist` 허용은 Googlebot·daumoa 같은 검색 로봇에게만.)
2. **기술적으로 열려 있다 ≠ 써도 된다**: 사진 서버(`cdnimg.melon.co.kr`, 구글 클라우드 저장소)는 `access-control-allow-origin: *`로 다른 사이트에서도 불러와지고 robots.txt도 없다. 하지만 이건 서버 설정일 뿐 이용 허락이 아니다.
3. **이용 허락이 없음**: 멜론은 스포티파이·유튜브와 달리 외부 표시를 허락하는 공개 API·개발자 약관이 없다. 프로필 사진의 저작권은 보통 소속사·사진가에게 있고, 멜론 약관은 서비스 콘텐츠를 정해진 용도(개인 감상) 밖에서 쓰는 것을 제한한다(약관 원문은 직접 확인 필요 — 검색으로는 원문을 못 찾음).
4. **대안이 있음**: 스포티파이(API 약관상 아티스트 이미지 표시 허용, 출처 표기)·유튜브(API로 받은 채널 썸네일 표시 허용, 30일마다 새로 받기)로 채운다.

→ 멜론은 링크(아티스트 페이지로 보내기)만 쓰고, 사진은 걸지 않는다.

## 유튜브 API 데이터 보관

YouTube API 정책상 API로 받은 데이터(채널 제목·썸네일 등)는 30일 안에 새로 받거나 지운다. `collect_yt_channels.py`는 확인한 지 30일이 지난 채널을 다시 묻는다(`REFRESH_DAYS`). 앱은 아바타 옆에 출처(유튜브)와 채널 링크(`page_url`)를 건다.

## 새 출처 시험 (2026-11-28 오후)

표본: 후보 상위 500 중 바로 듣기 없는 팀 50팀(A), 발매 기록(raw_kr_release)이 있는 미커버 팀 50팀(B — 발매곡 겹침 검증용).
상위 500 미커버 415팀 중 우리 발매 기록이 있는 팀은 27팀뿐이라(공연 위주 팀이 많음), '발매곡 겹침' 검증은 B에서만 의미가 있다.

| 출처 | A: 이름 유일 일치 | A: 미리듣기 | B: 일치 → 발매곡 겹침 확인 | 약관 |
|---|---|---|---|---|
| iTunes Search API (미국 스토어) | 15/50 (30%) | 15 | 18 → 9 | 조건부 허용 |
| Deezer 공개 API | 23/50 (46%) | 1 | 21 → 15 | 우리 용도엔 안 맞음 |
| 유튜브 채널 검색 (search.list) | 10회 중 9팀 맞는 채널 (눈 확인) | — | — | API 약관 안 |

**iTunes** — 한국 스토어(country=KR)는 음악 결과가 0이다(한국 iTunes 스토어는 음악을 팔지 않음). 미국 스토어에서 한글 이름으로 찾으면 영문 표기('Silica Gel')로 돌려주므로 연결표 별칭까지 같은 이름으로 본다.
- 눈 확인(A 일치 15팀): 12팀 맞음(예: 스키틀즈 'Youth Smash' = 유튜브 '청춘박살', 포스트이너서클 'Angel' = 싱글 '천사'), 1팀 동명 의심(소여 → 웹툰 테마곡), 2팀 판단 불가.
- 수집기 `collect_itunes.py`로 상위 대상 400팀을 보니 이름 일치 99팀. 그중 **확인 가능한 19팀 중 17팀이 맞음**(제목 겹침 3 + 첫 발매 연도 같음 14, 89%). 나머지 80팀은 우리 쪽 첫 발매일이 없어 확인할 수 없었다.
- 약관(Apple Search API 'Promo Content'): 그 콘텐츠를 홍보하는 페이지에서만 · 스트리밍만(내려받기·저장 금지) · "provided courtesy of iTunes" 표기 · iTunes/Apple Music 으로 가는 링크(배지) 옆에 · 분당 약 20번. → 주소만 저장하고, 앱은 `<audio>`(내려받기 버튼 숨김) + 출처 표기 + Apple Music 링크로 튼다.
- 지금은 **확인된 것(titles·year)만** players.csv 에 `kind=itunes`로 내보낸다(`collect_itunes.EXPORT_CONFIDENCE`). 이름만 일치한 것까지 넣으면 상위 500 바로 듣기가 크게 오르지만 약 1/10은 동명 다른 팀일 수 있다.

**Deezer** — 일치율은 높지만 쓰지 않는다: 개발자 약관이 비상업·개인 용도만 허용하고, 음원은 Deezer 위젯으로만 재생하게 하며, 콘텐츠(아티스트 사진 포함)를 다른 이미지와 결합하지 못하게 하고, API 사용 전 앱 승인을 받게 한다. 시험에서도 미리듣기가 있는 팀은 1/23뿐이었다(같은 팀이 앨범 있는 항목과 빈 항목으로 나뉜 경우가 많음).

**유튜브 채널 검색** — `yt_channel_search.py`: 하루 20번(2,000단위), 상위 300 중 바로 듣기·유튜브 링크 없는 팀. 시험 10팀의 실제 검색 결과를 정답지로 테스트(`tests/test_yt_channel_search.py`)에 넣었고, 표본 밖 10팀에서는 6팀을 자동으로 찾았다(눈으로 봐도 틀린 연결 없음). 공식 채널이 없으면 유튜브 자동 'Topic' 채널을 쓴다. 찾은 채널은 `collect_yt_channels`가 아바타·최신 영상을 받는다.

## 점검·보강 (2026-11-28 저녁)

**브라우저 확인** — 로컬 서버 + 크롬(화면 띄움, 소리만 끔)에서 iTunes 줄이 있는 3팀(eosa·Maggie's Garden·Naked Tapes)의 ▶ → 미니 플레이어를 실제 마우스 클릭으로 눌러 봄:
오디오가 불러와지고(readyState 4) 재생 시간이 늘어남(약 5초에 2.5~4.5초), 'provided courtesy of iTunes · Apple Music에서 듣기'와 링크가 보임,
홈으로 옮긴 뒤에도 같은 오디오가 계속 재생됨(재생 시간 계속 증가, 멈춤 아님). 유튜브 영상도 있는 팀은 첫 탭이 유튜브이고 'iTunes 30초 미리듣기' 탭으로 바꿀 수 있다.

**이름만 일치한 iTunes 82팀을 올릴 근거** — 찾지 못함, 등급 그대로(titles·year 만 앱에).
- 후보 근거: iTunes 장르의 한국 세부 장르(Korean Rock·Korean Indie·Korean Hip-Hop 등, 82팀 중 19팀 해당), 곡 제목의 한글(27팀), K-Pop 표기, 발매 연도와 우리 첫 등장 연도의 거리, 우리 유튜브 영상 제목과 곡 제목 겹침.
- 정밀도를 잴 수 있는 팀(제목·첫 발매일로 확인 가능)이 21팀뿐이고, 한국 세부 장르 규칙에 해당하는 확인 가능 팀은 3팀(모두 연도 불일치 — 데이터 오류일 수도 있음)이라 95%를 보일 수 없다.
- 영상 제목 겹침은 쓸 수 없다: 이름만 일치한 팀은 원래 바로 듣기가 없던 팀이라 유튜브 영상이 거의 없음.
- 눈으로 본 경향: 해외 팀 내한(Hard-Ons·David Grubbs·MONCHMONCH 등)은 이름이 같으면 대개 같은 팀이고, 흔한 한국 이름(진→다른 가수, 이브, 성용→트로트 커버)은 동명 위험이 크다.
- 주의: 지금 앱에 나가는 '소여'(year 등급)는 iTunes 쪽이 웹소설 테마곡 가수로 보여 동명 의심 — 연도 일치만으로는 이런 경우를 못 거른다. 연결 점검에서 사람이 확인 필요.

**유튜브 Topic 채널** — 'Topic'(유튜브 자동 채널)은 동명 위험이 커서(연결 점검에서 '허재혁 - Topic' 애매), 채널 검색 자동 연결은 그 채널 최신 영상 제목이 우리 발매 기록 제목과 겹칠 때만 한다(`verified`).
확인 안 된 Topic 은 `collect_yt_channels` 후보에서 빠지고(`prune` 으로 이미 붙은 것도 정리), 그 채널 영상(`raw_video_*_channels.csv`)은 내보내기에서 뺀다.

## 영문 활동명으로 찾기 (2026-11-28 저녁)

'소여' 처럼 iTunes·유튜브에 영문 이름('Sawyer')으로만 올라 있는 팀을 찾으려고, 검색 전용 영문 이름 파일을 만든다 — `scripts/en_names.py` → `data/raw/state/en_names.json`.
- 연결표(별칭)에는 넣지 않는다: 별칭은 팀 묶기에 쓰여서 검색용 후보가 섞이면 다른 팀이 합쳐질 수 있다.
- 출처(앞이 먼저): 원본 자료의 '한글 (English)' 표기 → 연결표 별칭 중 영문 → MusicBrainz 이름 → 스포티파이 매칭 이름 → (앞이 없을 때만) 팀 인스타 계정에서 뽑은 이름(band_sawyer → sawyer). 한글 이름 팀 3,118팀에 후보가 생겼다.
- `collect_itunes`: 팀 이름으로 확인 못 하면 영문 후보로 → 그래도 못 하면 우리 곡 제목(멜론 데뷔곡·발매 기록)으로 곡을 검색해 이름(영문 후보 포함)이 맞는 아티스트를 찾는다. 영문 이름은 동명 가수가 많아서(미국 스토어 'Sawyer' 수십 명) 아티스트 검색 + 아티스트별 곡 조회로 확인 규칙을 통과한 아티스트가 딱 하나일 때만 쓴다. 차단 목록의 iTunes 아티스트는 '못 찾음'으로 본다.
- `yt_channel_search`: 한글 이름으로 못 찾으면 영문 후보로 한 번 더(하루 상한 안에서), 이름 맞추기에도 영문 후보를 쓴다.
- 확인 규칙은 그대로(제목 겹침·첫 발매 연도, Topic 은 발매곡 겹침).
