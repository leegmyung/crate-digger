# 사진·바로 듣기 커버리지 (2026-11-28)

Chartmetric처럼 팀마다 **사진**과 **바로 재생**을 붙이기 위한 데이터 규칙. 앱 화면 연결은 UI 작업(`docs/app/player_pick.js`, `docs/app/db.js`)이 맡고, 여기는 데이터 쪽 규칙만 적는다.

## 대상 팀

`scripts/coverage_targets.py` — 오늘 점수(브라우저와 같은 `docs/lab/sql/candidates.sql`) 상위 500팀 → 그 밖의 정답 팀 순서.
`data/raw/state/coverage_targets.json`(비공개)에 저장하고, 하루 한도가 있는 수집기(스포티파이 검색·사진, MusicBrainz, 유튜브 채널)가 이 순서대로 먼저 처리한다. 같은 스크립트가 상위 300·500·정답 팀의 사진·바로 듣기 비율을 출력한다.

## 바로 듣기 — `docs/lab/data/players.csv`

팀마다 최대 2줄 (`scripts/players.py`, `export_lab_data.py`가 만든다).

| 칸 | 뜻 |
|---|---|
| `team_key` | 팀 키 |
| `kind` | `spotify`(아티스트 삽입 재생) / `youtube`(영상 삽입 재생) |
| `id` | spotify: `artist:<22자>` (player_pick.js `parseSpotifyRef`가 아티스트로 읽음) · youtube: 영상 번호 11자 |
| `title` | 영상 제목 (spotify는 빈칸) |
| `channel_title` | 영상을 올린 채널 (spotify는 빈칸) |
| `source` | 고른 근거: `spotify` / `official`(팀 공식 채널) / `stage`(무대 채널) / `search`(검색) |
| `published_at` | 영상 올린 날 `YYYY-MM-DD` (spotify는 빈칸) |
| `view_count` | 가장 최근 조회수 (`raw_video_stats`, 모르면 빈칸) |

**유튜브 대표 영상 고르는 순서** — 눌렀을 때 그 팀 음악이 나올 가능성이 높은 것부터:
1. 공식 채널 라이브(`official_live`), 최신
2. 공식 채널 음악 영상(제목에 MV·Official Audio·Lyric·Live 등), 최신
3. 무대 채널 영상(`stage`), 조회수 많은 것 → 같으면 최신
4. 공식 채널 그 밖의 영상(브이로그 등), 최신
5. 검색으로 찾은 영상(`search`), 조회수 → 최신

후보 영상은 `videos.csv`와 같은 걸러내기(이름 맞추기·인터뷰/쇼츠 제외)를 거친 **전체** 목록이다(`videos.csv`처럼 팀당 6개로 자르기 전).

## 사진 — `docs/lab/data/images.csv`

팀마다 1장: **스포티파이 아티스트 사진 → 없으면 유튜브 공식 채널 아바타**. 칸 `team_key, url, source, page_url`.
`page_url`은 출처 페이지(스포티파이 아티스트·유튜브 채널) — 사진 옆에 출처 링크를 걸 때 쓴다.
허용 주소: `i.scdn.co`, `yt3.ggpht.com`, `yt3.googleusercontent.com`의 https만 (앱 `db.js IMAGE_URL_RE`와 같음).

## 링크를 어디서 얻나

| 출처 | 얻는 것 | 비용·규칙 |
|---|---|---|
| 스포티파이 검색 (`collect_spotify.py`) | 아티스트 번호 + 검색 결과의 사진 | 하루 예산 공유(`spotify_budget.py`), 429면 그날 쉼 — 우회 안 함 |
| 스포티파이 사진 (`collect_artist_images.py`) | 사진 | 검색 때 받은 사진이 있으면 요청 안 함 |
| MusicBrainz (`collect_musicbrainz.py`) | 공식 유튜브 채널·스포티파이 번호·인스타 | 공개 API(robots 허용, 핵심 데이터 CC0), 2초 간격. 이름 키가 같은 한국 아티스트가 **딱 하나**일 때만, 짧은 이름·흔한 낱말은 안 물음 |
| 유튜브 공식 채널 (`collect_yt_channels.py`) | 채널 아바타·최신 영상 10개 | channels.list·playlistItems 각 1단위. search.list(100단위) 안 씀. 채널 주소는 links.csv·MusicBrainz·인스타 소개란에서만 |

**안 쓰는 방법과 이유**
- **유튜브 핸들 추측**(팀 이름으로 `@이름` 찾기): 2026-11-28 시험에서 공식 채널을 이미 아는 120팀에 해 봤더니 결과가 나온 59팀 중 **같은 채널 4팀, 같은 이름의 남의 채널 55팀** → 쓰지 않는다.
- **멜론 프로필 사진**: 아래 판단.

## 멜론 프로필 사진을 앱에 걸어도 되나 — 판단: 쓰지 않는다 (구현 안 함)

1. **주소를 얻는 단계부터 막힘**: `www.melon.com/robots.txt`는 일반 로봇(`User-agent: *`)에 `/global-k-chart`만 허용하고 나머지 전체(`Disallow: /`)를 막는다. 사진 주소는 아티스트 페이지에서만 나오므로, 주소를 모으려면 막힌 페이지를 읽어야 한다. (`/artist` 허용은 Googlebot·daumoa 같은 검색 로봇에게만.)
2. **기술적으로 열려 있다 ≠ 써도 된다**: 사진 서버(`cdnimg.melon.co.kr`, 구글 클라우드 저장소)는 `access-control-allow-origin: *`로 다른 사이트에서도 불러와지고 robots.txt도 없다. 하지만 이건 서버 설정일 뿐 이용 허락이 아니다.
3. **이용 허락이 없음**: 멜론은 스포티파이·유튜브와 달리 외부 표시를 허락하는 공개 API·개발자 약관이 없다. 프로필 사진의 저작권은 보통 소속사·사진가에게 있고, 멜론 약관은 서비스 콘텐츠를 정해진 용도(개인 감상) 밖에서 쓰는 것을 제한한다(약관 원문은 직접 확인 필요 — 검색으로는 원문을 못 찾음).
4. **대안이 있음**: 스포티파이(API 약관상 아티스트 이미지 표시 허용, 출처 표기)·유튜브(API로 받은 채널 썸네일 표시 허용, 30일마다 새로 받기)로 채운다.

→ 멜론은 링크(아티스트 페이지로 보내기)만 쓰고, 사진은 걸지 않는다.

## 유튜브 API 데이터 보관

YouTube API 정책상 API로 받은 데이터(채널 제목·썸네일 등)는 30일 안에 새로 받거나 지운다. `collect_yt_channels.py`는 확인한 지 30일이 지난 채널을 다시 묻는다(`REFRESH_DAYS`). 앱은 아바타 옆에 출처(유튜브)와 채널 링크(`page_url`)를 건다.
