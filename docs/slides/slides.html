Why

발굴

아직 작지만 신호가 있는 신인을 매일 자동으로 찾기

검수

플랫폼마다 다른 이름·표기·메타데이터를 하나로 맞추기

검증

역량

SQL 저장과 Tableau 지표 시각화로 실무형 파이프라인 구축

핵심 질문: "우리가 먼저 찾은 신인이, 나중에 정말 떴는가?"

02
Data

두 갈래로 후보를 모은다

해외 · GLOBAL

Bandcamp 중심

  • Bandcamp discover 포맷·장르별 랭킹 (바이닐, 디지털, 카세트) 매일 수집
  • KEXP 공개 API 라디오 편성 곡·레이블·발매일
  • MusicBrainz 오픈 메타데이터로 정제·연결
  • 매체 RSS로 평론 신호 (선정 여부만 기록)
국내 · KOREA

인디 신보 풀

  • 인디 유통사 카탈로그 (포크라노스 장르별 발매 목록)
  • Bandcamp 한국 아티스트 해외 수집기 재사용
  • 멜론·벅스 인디 최신, YouTube 인디 라이브
  • 킨디라운지·웹진으로 평론 신호

반응 지표: YouTube Data API (조회수·좋아요·댓글·구독자) + 타 플랫폼 입점 여부 (Spotify · Apple Music · Deezer · 멜론)

04
Metadata QA · SQL

같은 아티스트를 플랫폼 너머로 연결한다

테이블 (PostgreSQL)한 행역할
raw_gl_chart · raw_kr_release수집일 × 순위 / 신보 1건원본 보관, 재처리·감사 추적
artist_xref아티스트 × 플랫폼외부 ID, 매칭 방법, 신뢰도, 검수 상태
qa_issue검수 규칙 위반 1건누락·중복·표기 불일치 기록, 해결일
metric_snapshot날짜 × 아티스트 × 지표매일 쌓는 시계열 (소급 불가 → 지금부터)
watchlist · outcome_event선정 1건 / 공증 결과 1건선정·비교 그룹, 공증 발표일과 선행 기간

애매한 매칭은 수동 검수 대기열로 → 매칭률과 오류율 자체를 품질 지표로 공개

05
Validation

선정 그룹 vs 비교 그룹, 시간을 두고 비교

T0선정일 · 모든 지표 기준값
T+14단기 · 초기 반응 속도
T+90중기 · 성장 지속, 신규 입점
T+180~장기 · 규모 변화, 공증 결과
성장 배수

T0 대비 조회수·구독자 증가, 선정 vs 비교 중앙값

적중률

선정 아티스트 중 나중에 공증 프로그램에 뽑힌 비율

선행 기간

우리가 선정한 날부터 공식 발표까지 며칠 먼저 찾았나

재현율

공증 선정자 중 미리 찾아둔 비율, 놓친 이유 분석

비교 그룹 같은 시기·같은 풀에서 선정되지 않은 아티스트를 무작위 추출

성공 기준은 먼저 고정 예: 90일 성장 중앙값이 비교 그룹의 1.5배 이상
