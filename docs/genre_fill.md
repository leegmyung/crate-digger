# 장르 빈칸 채우기와 확신도 (2026-11-27)

팀 표(`docs/lab/data/teams.csv`)의 대표 장르가 **92.6% 빈칸**이었습니다. 장르가 비면 '같은 장르 안 비교'(`peer_compare.sql`)와 장르 필터가 거의 의미가 없습니다. 경쟁 서비스 Viberate에서도 장르 오분류가 비교를 망치는 것을 봤습니다([조사](research_2026-11-27_viberate_inside.md)).
그래서 빈칸을 줄이되, **얼마나 믿을 만한지(확신도)** 를 함께 남깁니다. 코드: `scripts/genre_fill.py`, 테스트: `tests/test_genre_fill.py`.

## 1. 원래 장르 추정의 입력 (바뀌기 전)

`export_lab_data.team_rows` → `build_dashboard_data._infer_genres`:
1. **플랫폼 장르** — 멜론 프로필 장르 + 발매 정보 장르(벅스·멜론·지니·플로·포크라노스)를 `config/genre_map.json`으로 큰 갈래에 묶은 것
2. 그게 없을 때만 **확실한 출처 힌트** — 리드머 소개 → 힙합, 상상마당 밴드 디스커버리 → 록·밴드 (정답 프로그램은 근거로 안 씀, 커밋 950deb7)
3. 사람이 확인한 장르(`config/genre_overrides.json`)가 있으면 그것

## 2. 빈칸을 줄일 재료 — 찾은 것과 못 쓴 것

| 재료 | 확인 결과 | 쓰나 |
|---|---|---|
| 멜론 프로필 장르 | 원본 CSV와 PostgreSQL 모두 480명(장르 있음 466명)으로 이미 다 쓰고 있음. 멜론 상세 페이지가 막혀 있어 당장 늘지 않음 | 그대로(늘면 자동 반영) |
| 매거진 리뷰 장르 태그 | 수집한 매체 CSV(IZM·음악취향Y·weiv·VISLA·트랙제로·overtone·힙합엘·리드머)에 **장르 칸이 없음** | 못 씀 (매체 페이지에서 장르를 새로 받아야 함) |
| 스포티파이 장르 | 스포티파이 프로필 43행 모두 장르 빈칸 | 못 씀 |
| **같은 무대 팀들의 장르** | 같은 날·같은 공연장에 선 팀 중 장르를 아는 팀의 다수결 | ✅ inferred |
| **공연장의 장르 성향** | 그 공연장에 선 장르 아는 팀들의 분포 | ✅ inferred (기준 엄격하게) |
| 힙합 전문 매체(힙합엘) 기사 | 힙합 47% · R&B 31% · 기타 22% | ✅ inferred (약한 힌트) |
| 유재하 음악경연대회 본선 | 포크·싱어송라이터 65% | ✅ inferred (약한 힌트) |
| 슈퍼루키(힙합·R&B 서바이벌) | 힙합/R&B 중 어느 쪽인지 갈 수 없음 | 안 씀 |
| 부산록페 루키 | 장르 아는 팀 5팀뿐, 포크 3·록 2 | 안 씀 |

맞는 비율은 **멜론 장르가 있는 팀으로 잰 값**입니다(그 팀의 장르를 가리고 추정해 비교).

## 3. 확신도(`genre_confidence`)와 채우는 순서

| 확신도 | 뜻 |
|---|---|
| `profile` | 멜론·발매 장르, 사람이 확인한 장르 |
| `press` | 확실한 출처 힌트(리드머·밴드 디스커버리) |
| `inferred` | 빈칸이던 팀만, 아래 ①→②→③ 중 처음 정해지는 것 |
| (빈칸) | 모름 |

1. **같은 무대 다수결** — 같은 날·같은 공연장에 선 다른 팀 중 장르를 아는 팀(profile·press)이 2팀 이상이고, 1등 장르가 60% 이상
2. **공연장 성향** — 그 팀이 선 공연장마다(장르 아는 팀 5팀 이상인 곳만) 장르 분포를 같은 무게로 합쳐 1등 장르가 **70%** 이상. 60%로 두면 맞는 비율이 51%로, 모든 팀을 '록'이라 찍는 기준선(46%)과 비슷해서 올렸습니다.
3. **약한 출처 힌트** — 힙합엘 기사 → 힙합, 유재하 경연 본선 → 포크·싱어송라이터

**순환 방지:** 투표는 profile·press 팀만 합니다. 추정한 장르(inferred)로 다시 다른 팀을 추정하지 않고, 한 번만 계산합니다.
**정답 정보 사용 금지:** 공연 신호와 신호 출처만 봅니다. 정답 프로그램(`csv_schema.OUTCOME_TIER`)은 힌트에서 뺍니다(테스트로 확인).
**시점:** 장르는 팀의 성격(잘 안 바뀜)이라 기준일과 무관하게 지금 정보로 정합니다. 점수 계산에는 장르가 들어가지 않습니다.

## 6. 요청 (다른 곳에 영향)

- **features.sql·앱 장르 필터:** `genre = '록·밴드'` 같은 필터에 추정(inferred) 팀이 들어오게 됩니다. 앱에서 확신도를 같이 보여 주거나(예: 장르 옆 '추정' 표시), 필터에 '확실한 것만' 선택지를 두는 것을 요청합니다. 점수 계산은 장르를 안 쓰므로 그대로입니다.
- **장르 편향 분석(`genre_bias.py` 등):** 장르별 성적을 잴 때는 profile·press만 쓸지, inferred까지 쓸지 정해야 합니다. 힙합엘 힌트로 힙합 팀이 크게 늘어 장르별 비교 숫자가 바뀝니다.
- **이웃 비교(`peer_compare.sql`):** 지금은 장르가 있으면 '단계+장르'로 묶습니다. 추정 장르로도 묶을지, profile·press만 쓸지 정하면 반영하겠습니다(`genre_confidence`를 읽게 바꾸면 됨).
- **재료 늘리기:** 매체 리뷰 페이지의 장르(IZM·음악취향Y 리뷰 본문에 장르 표기가 있으면) 수집, 멜론 프로필 수집이 풀리면 profile이 늘어 추정도 같이 좋아집니다.
