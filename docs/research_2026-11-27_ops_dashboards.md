# 매일 자동으로 받아 보는 업무 대시보드·리포트·관리 양식 조사 및 구조 재설계 제안 (2026-11-27)

목적: 앞선 두 조사(`docs/research_2026-11-27_dashboard_patterns.md` — 분석 차트 문법, `docs/research_2026-11-27_dashboard_samples.md` — 아티스트 상세·스카우팅 화면)와 겹치지 않게, **실제 현업에서 "매일·매주 자동으로 받아 보고, 관리자가 매번 조작하지 않아도 보기만 하면 판단이 끝나는" 대시보드·리포트·데이터 관리 양식 16곳**을 조사하고, Crate Digger 통합 앱(`docs/dashboard.html`)의 정보 구조·첫 화면 파티션·자동 요약·이상 감지·내보내기를 다시 설계한다.

조사 방법:
- 로그인·유료 결제가 필요한 서비스는 공개 기능 소개 페이지·공식 도움말·템플릿 디렉토리 기준으로 확인했다.
- 웹 확인은 `aside repl` 브라우저로 공식 페이지를 직접 열어 제목·목차·본문을 검증했다. (단, `docs.mixpanel.com`과 `amplitude.com`은 Aside 콘텐츠 필터에 차단되어 공식 문서 검색 요약 기준으로 정리했다.)

## 1. 음악 업계 — 자동 리포트 · 알림 · 스카우팅 양식 (6곳)

### ① Chartmetric — Report Center · Custom Alerts · Noteworthy Insights
- **링크**: https://chartmetric.com/features/report-center · https://chartmetric.com/features/custom-alerts
- **누가 언제 보나**: 레이블 A&R·마케팅·매니저가 매주 월요일 아침 또는 매일 아침 이메일·앱 알림으로 로스터·관심 리스트(Shortlist) 변화를 훑을 때.
- **첫 화면 구조(파티션)**: 왼쪽 메뉴의 `Report Center` 한 곳에 `Overview Reports(정기 요약)` · `Custom Alerts(조건 알림)` · `Noteworthy Insights(자동 이상 문장)` · `Milestone Monitor` · `Viral Video Alerts`를 묶어 둔다. 개별 아티스트 페이지를 일일이 열지 않고 "구독해 둔 변화"만 모아 본다.
- **'자동으로 알려 주는' 장치**:
  - **Noteworthy Insights**: 평소 흐름 대비 통계적으로 튄 변화(팔로워 급증, 플레이리스트 입성 등)만 골라 **자동 문장**으로 매일·매주 배달한다.
  - **Custom Alerts**: 절대치(Reach)·차이(Change)·변화율(% Change) 조건과 "미리보기 문장"을 제공해 임계치를 넘긴 대상만 띄운다.
- **내보내기 방식**: 일회성/정기 이메일 발송(최대 5명 CC), PDF 리포트 첨부, 표 단위 CSV.
- **가져올 점**: 평범한 숫자를 늘어놓지 않고 **"평소와 달라진 변화만 문장으로 먼저 요약"**하는 Noteworthy Insights 구조.
- **버릴 점**: 300~10,000개 규칙을 직접 짜야 하는 복잡한 Custom Alerts 설정 UI(우리는 규칙 설정 없이 자동으로 핵심 변화 4가지를 계산해 보여 주는 편이 맞다).

### ② Soundcharts — Weekly Reports · Discovery Notifications · Favorites
- **링크**: https://help.soundcharts.com/en/
- **누가 언제 보나**: A&R 스카우트·라디오/큐레이션 담당자가 관심 아티스트(Favorites)와 모니터링 대상 차트·플레이리스트의 주간 변동을 확인할 때.
- **첫 화면 구조(파티션)**: 왼쪽 사이드바에 `Favorites` 즐겨찾기 목록을 고정하고, 본문은 `Notifications` 피드와 `Rankings`(Favorites 필터 토글)로 나뉜다.
- **'자동으로 알려 주는' 장치**:
  - **Weekly Reports**: 최근 7일 하이라이트(Audience / Airplay / Playlists)를 원하는 요일에 자동 요약.
  - **Discovery Notifications**: 특정 차트·플레이리스트에 새 아티스트가 진입하면 알림을 띄우되, **차단 목록(Blocklist)**을 자동 적용해 유명 팀 잡음을 걸러낸다.
- **내보내기 방식**: 주간 요약 이메일, 순위 표 CSV.
- **가져올 점**: "새로 진입한 팀" 알림에 유명 팀 제외를 기본 적용하는 흐름, 그리고 사이드바에 가벼운 즐겨찾기 수만 표시하는 방식.
- **버릴 점**: 아티스트·곡·차트마다 종 아이콘을 눌러 개별 알림 규칙을 일일이 켜고 꺼야 하는 관리 부담.

### ③ Spotify for Artists — Home 요약 · Notification Center
- **링크**: https://support.spotify.com/us/artists/ (도움말 기준)
- **누가 언제 보나**: 아티스트·매니저·레이블 담당자가 매일 출근 직후 또는 발매 직후 "어제 무슨 일이 있었나" 30초 안에 확인할 때.
- **첫 화면 구조(파티션)**: 상단 우측 종 아이콘(빨간 점 = 읽지 않은 변화) + `Home` 탭의 최근 활동 요약 카드(상위 곡, 최근 청취자 증감, 에디토리얼 플레이리스트 추가). 여러 팀을 맡은 매니저는 별표(Star)한 팀만 알림 필터링 가능.
- **'자동으로 알려 주는' 장치**: 차트 진입, 플레이리스트 추가, 팔로워 이정표, 새 유입 경로를 **짧은 알림 한 줄 + 바로가기 링크**로 정리해 누르면 해당 근거 화면으로 바로 이동한다.
- **내보내기 방식**: 주간 요약 이메일, 표 우측 상단 CSV 다운로드.
- **가져올 점**: 알림 항목을 누르면 바로 해당 팀 상세로 이어지는 1클릭 동선, 그리고 별표(관심 팀)와 일반 전체를 깔끔하게 분리하는 구조.
- **버릴 점**: 개인 설정·비즈니스 이메일 확인처럼 로그인·계정 관리에 묶인 복잡한 알림 설정 단계.

### ④ Songstats — Milestone Alerts · Weekly Summary Email · 공유 카드
- **링크**: https://songstats.com/
- **누가 언제 보나**: 인디 레이블·매니저가 모바일과 웹에서 카탈로그의 새 이정표(플레이리스트, 차트, 라디오, 조회수 돌파)를 확인하고 팀/아티스트에게 공유할 때.
- **첫 화면 구조(파티션)**: 기간 토글(7일/28일/전체) + 성장 요약 카드(Growth Cards) + 시간 역순 Activity Feed.
- **'자동으로 알려 주는' 장치**: 최근 3개월 이내 신곡만 골라 알림을 줄 수 있고, 주간 요약 이메일(Weekly Summary)로 한 주 성과를 한 번에 묶어 준다.
- **내보내기 방식**: PDF·CSV 리포트 내보내기, 마일스톤을 바로 메신저·SNS에 붙일 수 있는 자동 요약 카드 생성.
- **가져올 점**: **공유/전달 목적이 분명한 "한 번에 복사·공유되는 주간 요약"** 개념(우리 앱에서는 "주간 요약 텍스트 복사" 버튼으로 구현).
- **버릴 점**: SNS 홍보용 아트워크 편집기처럼 발굴 분석과 무관한 마케팅 꾸미기 기능.

### ⑤ Luminate CONNECT — 정기 주간 리포트 · 다중 시트 Excel/CSV
- **링크**: https://luminatedata.com/music/ (공식 제품·도움말 기준)
- **누가 언제 보나**: 메이저 레이블·유통사 전략/데이터 담당자가 매주 금요일 주간 차트·스트리밍 집계를 회의 자료로 내보낼 때.
- **첫 화면 구조(파티션)**: `Charts`(주간 차트 표) · `Report Builder`(정기 순위/추세 리포트) · `Dashboard KPI Overview`로 분리되어 있으며, 시각 그래프보다 **필터가 적용된 데이터 그리드**가 중심이다.
- **'자동으로 알려 주는' 장치**: 일간/주간 예약 실행 리포트가 끝나면 Reports Manager에 자동으로 쌓인다.
- **내보내기 방식**: `EXPORT TO EXCEL` / `EXPORT TO CSV` — 특히 Excel/CSV 첫 시트(또는 상단 헤더)에 **적용된 기준일·필터 조건 요약**을 자동 포함하고, 파일명에 `종류_기준일.csv` 규칙을 붙여 나중에 열어봐도 언제 뽑은 파일인지 바로 알 수 있게 한다.
- **가져올 점**: CSV 파일명에 기준일과 화면 이름을 자동 포함(`crate_digger_candidates_2026-11-27.csv`), 현재 보고 있는 필터 그대로 1클릭 내려받기.
- **버릴 점**: 50,000행짜리 리포트 빌더·다중 ZIP 압축처럼 분석가가 매주 조립해야 하는 무거운 UI.

### ⑥ A&R 주간 스카우팅 시트 (업계 표준 워크플로: 월~금 리듬 + 4단 스키마)
- **링크**: https://www.notion.com/ko/templates/category/crm (Notion Record Label OS 및 Airtable + Soundcharts API 공개 워크플로 기준)
- **누가 언제 보나**: 레이블 A&R 팀이 월~화(후보 수집) → 수(실제 영상·음원·데이터 진위 확인) → 목(상위 3~5팀 선별) → 금(주간 리스닝 회의) 리듬으로 매주 반복 사용.
- **첫 화면 구조(파티션)**: 실제 시트는 4개 영역으로 구성된다 — ① 기본 정보(팀명·장르·소속/무소속·발굴 주간), ② **성장 속도**(총량보다 최근 7일/28일 변화), ③ **바로 듣기/보기 링크**(대표곡·라이브 영상), ④ **진행 단계**(신규 발굴 → 지켜보는 중 → 들어봄/접촉 → 보류/패스).
- **'자동으로 알려 주는' 장치**: 최근 업계에서는 Google Sheets 수동 복붙 대신 Airtable + 자동화(Make/API)로 매주 변화량만 자동 채워 넣고, 사람은 "이번 주 새 후보"와 "상위 3~5팀"만 듣는 방식으로 전환했다.
- **내보내기 방식**: 주간 회의용 "이번 주 TOP 5" 뷰 공유, 필요 시 CSV/시트 복사.
- **가져올 점**: **A&R이 실제로 매주 하는 일 = "이번 주 새로 뜬 3~5팀을 보고, 영상/음원을 바로 들어보고, 계속 지켜볼지 넘길지만 정하는 것"**. 첫 화면이 정확히 이 금요일 리스닝 시트처럼 읽히면 별도 조작이 필요 없다.
- **버릴 점**: 20개 열(담당자, 연락처, 계약 조건, 법무 단계 등)을 매번 손으로 채워야 하는 입력 폼(우리는 "확인"이 목적이므로 수동 입력을 강요하지 않는다).

## 2. 운영 대시보드 · 자동 요약 · 이상 감지 (7곳)

### ⑦ Google Analytics 4 — Automated Insights (자동 이상 감지 문장)
- **링크**: https://support.google.com/analytics/answer/9443595
- **누가 언제 보나**: 사이트/서비스 운영자가 복잡한 탐색 보고서를 열지 않고 홈 화면에서 "이번 주 평소와 다르게 튄 일"만 빠르게 확인할 때.
- **첫 화면 구조(파티션)**: 홈 화면 상단에 7일 추세 카드(실선=이번 주 vs 점선=지난주)를 두고, 바로 아래 **Insights 카드 묶음**을 배치한다.
- **'자동으로 알려 주는' 장치**: 사용자가 아무 규칙도 설정하지 않아도 통계 모델로 평소 대비 급등·급락을 감지해 **"OO 지표가 지난주 대비 +42% 상승했습니다"** 형태의 자연어 문장 카드로 자동 노출한다. 카드를 누르면 원인 상세가 펼쳐진다.
- **내보내기 방식**: 맞춤 통계 발생 시 이메일 자동 발송, 보고서 CSV/PDF 내려받기.
- **가져올 점**: **설정을 건드리지 않아도 첫 화면 최상단에 "이번 주 변화"를 한국어 자연어 문장으로 자동 생성**하는 패턴.
- **버릴 점**: 머신러닝 민감도·학습 기간(90일/32주) 같은 통계 파라미터 설정 UI 노출.

### ⑧ Amplitude / Mixpanel — Dashboard & Board Subscriptions · KPI Digest
- **링크**: Amplitude Docs (*Subscribe to a dashboard*) · Mixpanel Docs (*Boards & Alerts*) — *(Aside 콘텐츠 필터 차단으로 공식 문서 검색 요약 기준)*
- **누가 언제 보나**: 프로덕트 매니저·임원이 매일/매주 아침 대시보드에 직접 로그인하지 않고 슬랙·메일로 핵심 지표 다이제스트를 받아 볼 때.
- **첫 화면 구조(파티션)**: 보드 상단 8개 핵심 카드만 다이제스트에 자동 포함(카드 수 상한으로 정보 과부하 방지)하고, 나머지는 "전체 보드 보기" 링크로 넘긴다.
- **'자동으로 알려 주는' 장치**: 정기 스냅샷(일간/주간) + 임계치/이상 감지 알림(Alerts) + AI KPI Agent의 자동 변화 요약 문장.
- **내보내기 방식**: HTML 요약 메일(선택적 CSV 첨부), Slack 요약 메시지.
- **가져올 점**: **첫 화면/다이제스트에 담는 카드 수를 엄격히 제한**(핵심만 3~4덩어리)하고, 세부는 링크로 넘기는 절제.
- **버릴 점**: 이벤트 세그먼테이션·퍼널 빌더처럼 사용자가 매번 쿼리를 조립해야 하는 작업대 화면을 기본 홈으로 쓰는 구조.

### ⑨ Metabase — Dashboard Subscriptions · "결과 없으면 생략"
- **링크**: https://www.metabase.com/docs/latest/dashboards/subscriptions
- **누가 언제 보나**: 비개발자 팀원·운영자가 SQL을 몰라도 매일 아침 정기 리포트를 메일/슬랙으로 받아 보거나 웹 대시보드를 열어 볼 때.
- **첫 화면 구조(파티션)**: 깔끔한 상단 제목 + (있으면) 최소 필터 1~2개 + 카드 그리드. 각 카드에 마우스를 올렸을 때만 `...` 메뉴(다운로드 등)가 조용히 나타난다.
- **'자동으로 알려 주는' 장치**: **"결과가 없으면 보내지 않기(Don't send if there aren't results)"** 옵션과 목표선 돌파 알림(Alert). 즉, 이상이나 새 항목이 없을 때는 소음을 만들지 않는다.
- **내보내기 방식**: 대시보드 우측 상단 공유/내보내기 메뉴 한 곳(PDF) + 카드별 `.csv`/`.xlsx`/`.json` 다운로드.
- **가져올 점**: **평소 정상일 때는 조용히 한 줄, 이상이 있을 때만 눈에 띄는 경고 배너**를 띄우는 무소음 원칙, 그리고 내보내기를 `내보내기 ▾` 한 곳에 숨겨 평소 화면을 깨끗하게 유지하는 방식.
- **버릴 점**: 구독자·SMTP·권한 관리 같은 다중 사용자 어드민 설정.

### ⑩ Looker — Scheduled Deliveries & Alerts (정기 요약 vs 조건 알림 분리)
- **링크**: https://docs.cloud.google.com/looker/docs/scheduling-and-sending-dashboards
- **누가 언제 보나**: 경영진(정기 주간 리포트)과 실무 운영자(특정 지표 이상 시 즉시 알림)가 같은 데이터를 서로 다른 호흡으로 볼 때.
- **첫 화면 구조(파티션)**: 대시보드는 "요약 숫자 → 핵심 추세 → 상세 표" 3단으로 단순하게 두고, 탐색(Explore)과 SQL은 별도 깊은 메뉴로 분리한다.
- **'자동으로 알려 주는' 장치**: **정기 브리핑(Schedule)**과 **이상 알림(Alert)**을 명확히 분리한다. 브리핑은 "매주 훑는 습관", 알림은 "문제가 생겼을 때만 보는 예외"다.
- **내보내기 방식**: CSV, Excel, PDF, Google Sheets 전송.
- **가져올 점**: 우리 앱의 **'매일 보는 브리핑(발굴)'**과 **'궁금할 때만 여는 고급·검증(백테스트·SQL)'**을 계층적으로 완전히 갈라놓는 정보 구조.
- **버릴 점**: LookML/Explore 같은 무거운 셀프서비스 BI 편집 화면.

### ⑪ Datadog / Grafana — Monitor Summary Widget (0건 숨김 · 이상 우선)
- **링크**: https://docs.datadoghq.com/ko/dashboards/widgets/monitor_summary/ · https://grafana.com/docs/grafana/latest/alerting/
- **누가 언제 보나**: 시스템/데이터 파이프라인 운영자가 "어젯밤 배치·수집이 문제없이 돌았는지" 1초 만에 확인할 때.
- **첫 화면 구조(파티션)**: 상단에 상태별 카운트(`정상 / 주의 / 실패`)를 요약하고, **`hide_zero_counts` 옵션으로 문제가 없는 항목(0건)은 숨겨** 이상이 발생한 항목만 전면에 올린다.
- **'자동으로 알려 주는' 장치**: 상태 우선 정렬(`triggered` / `status` 순)로 정상 소스 10개를 일일이 읽지 않아도 실패·급감 소스 1개만 맨 위에 바로 뜬다.
- **내보내기 방식**: 장애 요약 링크 공유, 알림 채널 연동.
- **가져올 점**: 매일 21시 자동 수집이 정상일 때는 브리핑 안에 조용히 **"수집 정상 (10/10 소스 · 기준 2026-11-27)"** 한 줄만 표시하고, **소스 실패(`file_ok: false`)·수집 지연(2일 이상 미갱신)·건수 급감(0건 또는 최근 평균 대비 50% 이상 급락)**이 감지되면 첫 화면 최상단에 자동 경고 배너를 띄워 관리자가 품질 탭을 따로 열어보지 않아도 즉시 알게 만들기.
- **버릴 점**: 엔지니어용 시계열 메트릭 쿼리·노이즈 많은 로그 스트림.

### ⑫ Stripe Dashboard Home — "Today" 비교 + 최상단 알림 + 조용한 내보내기
- **링크**: https://docs.stripe.com/dashboard/basics
- **누가 언제 보나**: 사업자·운영 책임자가 매일 대시보드에 들어와 "오늘 vs 어제" 흐름과 처리할 예외가 있는지만 10초 만에 볼 때.
- **첫 화면 구조(파티션)**:
  - **최상단**: 처리 필요한 예외/경고가 있을 때만 뜨는 얇은 배너(없으면 아예 안 보임).
  - **상단 `Today` 영역**: 오늘 vs 어제(지난 기간) 비교 수치와 핵심 잔액/요약.
  - **하단 `Your overview`**: 핵심 지표 카드 묶음(기본값만으로도 완성, 편집은 숨겨진 버튼).
  - **왼쪽 메뉴**: 핵심 5~6개만 깔끔하게 노출하고, 개발자/SQL(Sigma)·세부 보고서는 아래쪽 접힘 메뉴로 내린다.
- **'자동으로 알려 주는' 장치**: 모든 숫자가 어제/지난주 대비 변화량과 함께 자동 표시되며, 홈에서는 불필요한 필터 바를 아예 노출하지 않는다.
- **내보내기 방식**: 홈 화면에는 내보내기 버튼을 어지럽게 두지 않고, 표 화면(Transactions 등) 우측 상단의 조용한 `Export` 버튼 하나로 현재 필터된 결과를 CSV로 내려받는다.
- **가져올 점**: **홈 화면에서 전역 필터 바·초기화·가중치 컨트롤을 걷어내 "보기만 하는 화면"으로 만드는 과감한 정리**, 그리고 예외가 있을 때만 최상단 경고 배너를 띄우는 규율.
- **버릴 점**: 위젯 드래그 편집(`Add`/`Edit` 커스터마이징) — 사용자가 직접 화면을 조립해야 하는 수고는 만들지 않는다.

### ⑬ Linear — Inbox (Priority / Other) & Triage
- **링크**: https://linear.app/docs/inbox
- **누가 언제 보나**: 제품 팀원이 매일 아침 "내가 놓치지 말아야 할 새 변화"만 빠르게 훑고 넘길 때.
- **첫 화면 구조(파티션)**: 전체 이슈 목록과 별개로 **Inbox(새로 들어온 변화)**를 맨 위에 두고, **Priority(중요 변화)**와 **Other(나머지)** 두 갈래로 자동 분류한다. 항목을 누르면 오른쪽/하단에 상세가 바로 열려 화면 맥락을 잃지 않는다.
- **'자동으로 알려 주는' 장치**: 이미 읽은 항목은 다이제스트에서 자동 제외하고, 중요한 변화만 맨 위로 끌어올린다.
- **내보내기 방식**: 링크 복사(URL 기반 공유), CSV 내보내기(설정/뷰 메뉴).
- **가져올 점**: 첫 화면을 **"이번 주 새로 생긴 변화(Inbox형 브리핑)"**로 구성하고, 중요한 후보(TOP 5 + 최대 상승 + 새 영상)를 Priority처럼 먼저 보여 준 뒤 나머지는 펼치기/목록으로 넘기는 흐름.
- **버릴 점**: 모든 항목을 일일이 Accept/Decline/Snooze 처리해야 비워지는 강제 Triage 의무(우리 사용자는 "보고 확인"이 목적이므로 처리 의무를 지우지 않는다).

## 3. 데이터 관리 양식 · 파이프라인 보드 (3곳)

### ⑭ Airtable Interface Designer — 원본 표 숨기고 "보는 화면"만 제공
- **링크**: https://www.airtable.com/platform/interface-designer · https://www.airtable.com/templates
- **누가 언제 보나**: 데이터 관리자가 만든 원본 DB(Base)를 비개발자 실무자·의사결정자가 "읽기 전용에 가까운 깔끔한 앱 화면"으로 매일 확인할 때.
- **첫 화면 구조(파티션)**: 원본 시트(열 20개짜리 표)를 그대로 보여 주지 않고, 용도별 4가지 인터페이스 레이아웃 중 하나를 씌운다 — ① **Dashboard**(요약 숫자+핵심 변화), ② **List/Grid**(정렬 가능한 목록), ③ **Record Review**(한 대상 상세 + 첨부 영상/링크), ④ **Kanban**(단계별 보드).
- **'자동으로 알려 주는' 장치**: 연결된 테이블의 최근 기록(예: 새 신호, 최근 활동일)을 Rollup으로 자동 집계해 카드에 뱃지로 붙인다.
- **내보내기 방식**: 뷰 메뉴의 `Download CSV`, 공유 링크.
- **가져올 점**: **원본 DB(`signals`, `teams`, `outcomes`, SQL)는 완전히 뒤에 숨기고, 사용자 앞에는 읽기 편한 요약·목록·상세 화면만 놓는 철학**이 우리 원칙("관리자가 다루지 않고 자동으로, 보기만 하면 안다")과 정확히 일치한다.
- **버릴 점**: 사용자가 직접 인터페이스 블록을 편집하는 빌더 UI.

### ⑮ Notion — 같은 DB의 다중 뷰 (이번 주 표 · 파이프라인 보드 · 갤러리)
- **링크**: https://www.notion.com/ko/templates/category/crm
- **누가 언제 보나**: 소규모 팀·1인 운영자가 같은 아티스트/CRM 목록을 상황에 따라 "이번 주 새 항목 표" 또는 "단계별 보드"로 전환해 볼 때.
- **첫 화면 구조(파티션)**: 한 페이지 상단에 `표 | 보드` 작은 탭만 두고, 같은 데이터를 다시 입력하지 않고 보기 방식만 바꾼다. 각 항목을 클릭하면 상세 페이지가 열려 영상·링크·메모를 한 번에 본다.
- **'자동으로 알려 주는' 장치**: 날짜 필터 기반 자동 뷰(`최근 7일 추가됨`)로 매주 수동으로 시트를 복사하지 않아도 최신 항목이 자동 집계된다.
- **내보내기 방식**: 페이지/DB 메뉴의 CSV·Markdown 내보내기, 링크 복사.
- **가져올 점**: **`관심 목록` 안에서만 선택적으로 `표 | 보드` 전환**을 제공해, 가볍게 볼 사람은 표로 보고 파이프라인 관리가 필요한 사람만 보드로 볼 수 있게 하는 유연성.
- **버릴 점**: 빈 속성 칸이 주렁주렁 달린 위키 폼 UI(정보가 없는 필드는 아예 숨긴다).

### ⑯ Pipedrive — 단계별 파이프라인 보드 (정체 경고 · 최소 입력)
- **링크**: https://www.pipedrive.com/en/features/pipeline-management
- **누가 언제 보나**: 영업/스카우팅 담당자가 여러 후보 중 "어디에 관심 팀이 몰려 있고, 최근 새 움직임이 생긴 팀이 누구인지" 한눈에 파악할 때.
- **첫 화면 구조(파티션)**: 3~5개 단계 열(칼럼)에 간결한 카드(이름, 핵심 수치 1개, 최근 활동 배지 1개)만 배치.
- **'자동으로 알려 주는' 장치**: 최근 새 활동이 있거나 오래 방치된 카드에 작은 상태 점/배지를 자동 표시해 따로 기억하지 않아도 눈에 띈다.
- **내보내기 방식**: 목록 뷰에서 `Export filter results (CSV/Excel)`.
- **가져올 점**: `관심 목록`에 굳이 복잡한 CRM을 도입하지 않더라도, **기본값 `지켜보는 중` → 필요할 때만 1클릭으로 `들어봄` / `보류` 전환**할 수 있는 초경량 3단계 상태(입력 강제 0).
- **버릴 점**: 금액 예측, 마감일 강제 입력, 담당자 배정 같은 영업 전용 필수 필드.

## 5. [2단계] 대시보드 구조 재설계 제안 (구현 전 보고)

### 5-1. 현재 10개 화면 정리표 (합칠 것 · 숨길 것 · 없앨 것)

### 5-5. 데이터 이상 자동 표시 규칙 (관리자가 확인 안 해도 눈에 띄게)

앱이 열릴 때 `docs/data/collect.json`, `docs/data/dashboard.json`, `docs/lab/data/meta.json`을 자동으로 읽어 아래 4가지 조건을 검사한다:
1. **소스 수집 실패**: `collect.json`의 `runs` 중 `file_ok === false` 또는 `dashboard.json`의 `errors.length > 0`
2. **수집 건수 0건 / 급감**: `collect.json`의 `runs` 중 `rows === 0`인 소스, 또는 `dashboard.json` `gigs_by_month` 최신 완성 월 건수가 직전 3개월 평균 대비 50% 이상 급감
3. **수집 지연(갱신 멈춤)**: `meta.data_end` 또는 `collect.generated`가 브라우저 현재 날짜보다 3일 이상 과거일 때 (로컬 테스트 시엔 `meta.data_end` 대비 `collect.json` 날짜 차이도 함께 확인)
4. **심각 품질 오류**: `dashboard.json` `sections.quality`에 `level === 'error'` 항목이 있을 때

- **정상일 때**: 경고 배너를 아예 띄우지 않고, 헤더 상태 줄과 브리핑 문장에 조용히 `수집 정상 (10/10 소스)`만 표시.
- **이상이 1건 이상일 때**: **어느 화면에 있든 최상단에 노란/빨간 경고 배너**를 자동 노출하고, 원인을 한 줄로 설명 + `수집 현황 보기` 버튼 제공.

### 5-6. 스포티파이·유튜브 바로 듣기 + 아티스트 사진 배치 & 완성도 고도화 (사용자 결정 반영)

사용자 결정에 따라 **외부 플랫폼은 스포티파이와 유튜브 2개만** 유지하고(멜론·지니·벅스 메뉴 제거), 사진·바로 듣기를 4원칙에 맞춰 아래처럼 통합 설계한다.

#### 1) 실제 데이터 커버리지 확인 (2026-11-27 기준)
- `docs/lab/data/images.csv`: **241팀** (`source=spotify`, `https://i.scdn.co/image/...` 유효 URL; 추후 유튜브 채널 썸네일 보강 가능).
- `docs/lab/data/links.csv`: 스포티파이 연결 **267팀** 전원 `https://open.spotify.com/artist/<22자 ID>` 정규식 통과.
- 현재 후보 스냅샷 기준: **TOP 5 중 3팀(60%)**(`품바21`, `언오피셜`, `롱타임노쉿`)이 스포티파이 사진·바로 듣기 즉시 지원, `포져군단`은 무대 영상 6개 보유.

#### 2) 플랫폼 단순화 규칙 (스포티파이 · 유튜브만)
- **멜론 · 지니 · 벅스 등 국내 음원 검색 메뉴 제거**: 드롭다운 메뉴 잡음을 없애고 **Spotify / YouTube** 2개 축으로만 명확히 연결.
- **유튜브 연결 우선순위**:
  1. `links.csv`에 **유튜브 공식 채널**이 있으면 공식 채널로 바로 연결
  2. 공식 채널이 없고 `videos.csv`에 **무대 영상**이 있으면 **최근 무대 영상**으로 바로 연결(또는 대시보드 내 클릭 재생)
  3. 둘 다 없을 때만 유튜브 검색 링크로 폴백

#### 3) 아티스트 사진(`ArtistAvatar`) 우선순위 & 배치 규칙
- **사진 폴백 체인 (3단계)**:
  1. **스포티파이 아티스트 사진** (`images.csv` `source=spotify`, `https://i.scdn.co/` 화이트리스트)
  2. **유튜브 채널 썸네일** (`images.csv` 유튜브 소스 확장 시 `yt3.ggpht.com` / `yt3.googleusercontent.com` 등 https 화이트리스트)
  3. **이름 첫 글자 + 장르색 저채도 모노그램** (사진 없거나 `onerror` 시 깨진 이미지 아이콘 절대 노출 금지)
- **CLS(레이아웃 흔들림) 방지**: 모든 이미지에 고정 `width`/`height` + `aspect-ratio: 1 / 1` + `object-fit: cover` + `loading="lazy"` + `decoding="async"` + `alt="<팀 이름>"` 적용.
- **화면별 크기·형태 및 출처 표기**:
  | 위치 | 크기·형태 | 출처 표기 (Spotify 가이드라인) |
  |---|---|---|
  | **이번 주 브리핑 TOP 5 카드** | `48×48px` 둥근 사각(`radius 10px`) | 섹션 하단 작은 각주 `사진 출처: Spotify / YouTube` |
  | **후보 목록 / 관심 목록 / 브리핑 변동 표** | `28×28px` 원형(`radius 50%`) | 표 하단 작은 각주 `사진 출처: Spotify / YouTube` |
  | **팀 상세 헤더** | `72×72px` 둥근 사각(`radius 14px`) | 사진 바로 아래 `11px` muted 링크 `사진 · Spotify ↗` (또는 유튜브 출처) |

#### 4) 스포티파이 바로 듣기 플레이어 (`SpotifyInlinePlayer` — Lazy Click-to-Load)
- **ID 보안 검증**: `links.csv`의 `platform='spotify'` URL에서 정규식 `/^https:\/\/open\.spotify\.com\/artist\/([A-Za-z0-9]{22})(?:[/?#].*)?$/`로 22자 ID만 추출.
- **초기 iframe 0개 원칙**: 페이지 로드 시 iframe을 미리 생성하지 않고, **`▶ 듣기`**를 누르는 순간 그 자리에서 공식 임베드 생성(`https://open.spotify.com/embed/artist/<id>?utm_source=generator&theme=0`, `height="152"`, `loading="lazy"`, `allow="autoplay; clipboard-write; encrypted-media; fullscreen; picture-in-picture"`).
- **단일 활성 플레이어 규칙**: 다른 팀의 `▶ 듣기`를 누르면 이전 플레이어는 자동 닫힘(중복 재생·iframe 누적 방지).
- **화면별 배치 (코디네이터 선행 구현 기반 위에 구조 재설계 통합)**:
  1. **이번 주 브리핑 TOP 5 카드**: `[48px 사진/모노그램]` + `팀 이름 · 장르` + `왜 볼 만한가(평문 1줄)` + `[▶ 듣기]`(스포티파이) 또는 `[▶ 영상]`/`[유튜브]`(공식 채널 → 최근 무대 영상).
  2. **후보 목록 / 관심 목록 / 브리핑 변동 행**: `28px` 썸네일 + 스포티파이 팀은 작은 `▶` 클릭 시 인라인 `152px` 플레이어 생성, 미보유 팀은 유튜브(공식 채널 → 최근 무대 영상) 연결.
  3. **팀 상세 헤더 (`#/team/:key`)**: `[72px 사진 + 출처]` + `▶ 스포티파이 바로 듣기` + `YouTube(공식 채널 또는 최근 무대 영상)` 버튼 2개 중심으로 깔끔히 정돈.

#### 5) "데이터 나열 → 완성도 있는 제품" 4대 시각 고도화 원칙
1. **시각적 앵커**: 모든 팀 카드·행·헤더에 `스포티파이 → 유튜브 썸네일 → 첫 글자 모노그램` 아바타를 배치해 텍스트 벽 느낌 제거.
2. **이탈 없는 즉시 검증**: 스포티파이 바로 듣기 + 유튜브 공식 채널/최근 무대 영상 2개 축만으로 군더더기 없이 귀·눈 검증.
3. **정보 위계와 여백**: 1화면 = 상단 평문 브리핑 → 시각 카드 → 변동 2단 → 최근 무대 영상으로 호흡을 나누고, 숫자(점수·순위·증감)는 보조 메타로 정돈.
4. **화이트/트루 블랙 양쪽 완성도**: 사진 테두리(`1px solid var(--border)`), 모노그램 저채도 배경, Spotify 임베드 컨테이너 라운딩(`12px`), 375px 모바일 반응형까지 양쪽 테마에서 일관된 마감.
