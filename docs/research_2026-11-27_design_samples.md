# 대시보드 디자인 시안 후보 (2026-11-27)

> **이 문서의 쓰임**: 사용자가 "디자인·구조가 아직 투박하다, 비슷한 대시보드 샘플과 샘플 모음 사이트를 찾아 달라 — 내가 고르겠다"고 해서 만든 **고르기용 목록**이다.
> 앞선 조사 3개(`research_2026-11-27_dashboard_patterns.md`·`_dashboard_samples.md`·`_ops_dashboards.md`)는 **무슨 기능을 어디에 둘지(구조)**를 봤고, 이 문서는 **어떻게 보이게 할지(생김새·분위기)**를 본다. 겹치는 서비스(Chartmetric 등)는 여기서는 "화면 생김새" 관점만 적었다.
>
> 조사 방법: 웹 검색과 공개 페이지만 확인했다(로그인·브라우저 조종 없음). 유료 서비스는 회사 소개 페이지·도움말·블로그 화면 기준이라 **실제 화면과 조금 다를 수 있다.** "공개" 칸에 직접 열어 볼 수 있는지 적었다.

## 0. 먼저 결론 — 고를 것 3가지

| | 시안 A · 분석 도구형 | 시안 B · 조용한 업무 도구형 | 시안 C · 에디토리얼(잡지)형 |
|---|---|---|---|
| 한 줄 | 야구 기록 사이트처럼 **숫자를 촘촘하게, 백분위 막대로** | Linear처럼 **흑백 + 강조색 하나, 선 얇게, 목록↔상세 빠르게** | 공연 잡지처럼 **글·제목이 앞에, 활동 기록을 기사처럼** |
| 대표 참고 | Baseball Savant · FBref · Chartmetric | Linear · Vercel(Geist) · Plausible | Resident Advisor · The Pudding · Kworb |
| 잘 맞는 때 | 숫자 근거를 바로 보고 싶을 때 | 매일 열어서 빨리 훑을 때 | 처음 보는 사람·면접관에게 보여 줄 때 |
| AI틱함 피하기 | 강함 (스포츠 기록 사이트는 '사람이 만든' 느낌이 강함) | 보통 (잘못하면 흔한 SaaS 템플릿처럼 보임) | 가장 강함 (글꼴·여백이 개성) |
| 작업 크기 | 중간 (점수 근거 부분 새로 그림 + 백분위 계산) | 작음~중간 (색·선·간격 정리 중심) | 큼 (글꼴·화면 배치 크게 바뀜) |

**제안(고르는 건 사용자)**: **B를 뼈대로, A의 '백분위 막대'를 팀 상세 점수 근거에만 빌려 오기.** 지금 앱의 구조(순위표 → 팀 상세)를 크게 안 바꾸고도 '투박함'이 가장 빨리 사라진다. C는 첫 화면·주간 브리핑처럼 '읽는' 화면에만 섞는 쪽이 현실적이다. 자세한 비교는 3장.

## 1. 실제 제품 화면 15개

각 항목: **링크 · 우리와 닮은 점 · 빌려올 점 3개 · 공개 여부**.

### 음악 — A&R·아티스트 분석

#### ① Chartmetric — 아티스트 분석 화면
- 링크: https://chartmetric.com/features/artist-analytics · 대시보드 소개 https://chartmetric.com/products/dashboard · 아티스트 개요 화면 개편 글 https://hmc.chartmetric.com/chartmetric-artist-overview-page/
- 닮은 점: 아티스트 한 명을 누르면 점수·지표·사건 기록·비슷한 아티스트가 한 화면에 나온다 — 우리 '팀 상세'와 거의 같은 역할.
- 빌려올 점:
  1. **(팀 상세)** 맨 위에 '이 팀의 단계(신인/성장/중견)' 꼬리표 + 점수 하나만 크게, 나머지는 아래로 — 첫눈에 읽을 숫자를 하나로 줄인다.
  2. **(표)** '비슷한 규모의 이웃 아티스트'를 위아래로 나란히 놓는 표 — 우리 '관계망'과 별개로 "같은 단계 팀 중 몇 위"를 보여 주기 좋다.
  3. **(색)** 플랫폼마다 아이콘·색을 고정해서 출처를 글 대신 아이콘으로 구별 — 우리 4갈래(발매·공연·선정·큐레이션)에 색 4개를 고정하면 된다.
- 공개: 소개 페이지·블로그 화면은 공개. 실제 앱은 가입 필요(카드 없이 7일 체험).

#### ② Soundcharts — A&R 리서치 화면
- 링크: https://www.soundcharts.com/en/ar-research-and-business-facing-music-discovery · 아티스트 프로필 설명 https://help.soundcharts.com/en/articles/3192706-what-is-an-artist-full-data-profile
- 닮은 점: "발굴(discovery)" 목록에서 조건으로 거르고 → 아티스트 프로필로 들어가는 흐름. 차단 목록(이미 큰 팀 빼기)도 우리 '후보 제외 목록'과 같다.
- 빌려올 점:
  1. **(필터)** 순위표 위에 **조건을 문장처럼 쌓는 필터**("장르 = 록 · 첫 발매 2년 이내 · 공연 3회 이상") — 지금의 버튼 나열보다 무엇이 걸렸는지 잘 보인다.
  2. **(그래프)** 지표 그래프에 사건(차트 진입·라디오 첫 송출)을 **점으로 찍어 겹쳐** 보여 줌 — 우리 활동 기록을 시간 막대 위에 점으로 찍으면 된다.
  3. **(표)** 처음엔 줄 수를 제한하고 "더 보기"로 숨김 — 우리 순위표도 처음엔 20줄만.
- 공개: 소개·도움말 공개. 무료 가입 시 최근 28일·줄 수 제한, 전체 프로필은 유료.

#### ③ Viberate — 아티스트 페이지 · 발굴 차트
- 링크: 아티스트 페이지 설명 https://viberate.com/blog/music-analytics/viberates-artist-page-everything-you-wanted-to-know-at-a-glance · 분석 소개 https://www.viberate.com/artist-analytics
- 닮은 점: 아티스트마다 **누구나 볼 수 있는 공개 페이지**가 있고, 그 위에 "한눈에 보는" 요약 카드를 둔다.
- 빌려올 점:
  1. **(팀 상세)** 맨 위 요약 띠에 '채널별 숫자 4~5개'를 같은 폭 칸으로 가로 배치 — 우리 4갈래 건수를 이렇게 놓으면 된다.
  2. **(필터)** "인디/무소속만", "팔로워 N 이하" 같은 **상한선 필터** — "아직 작은 팀"을 고르는 우리 목적과 똑같다.
  3. **(배지)** 'HOT'처럼 짧은 배지 하나만 — 배지를 여러 개 붙이지 않는 절제.
- 공개: 아티스트 기본 페이지는 공개·무료. 자세한 분석은 유료(무료 체험 있음).

#### ④ Songstats — 활동 피드
- 링크: https://songstats.com/ (화면 캡처가 있는 소개 https://apis.io/providers/songstats/)
- 닮은 점: 플레이리스트 추가·차트 진입·라디오 송출 같은 **사건을 시간 역순 피드**로 쌓는다 — 우리 '활동 기록'과 같다.
- 빌려올 점:
  1. **(활동 기록)** 한 줄 = 출처 아이콘 · 날짜 · 한 문장 · 원문 링크. 줄마다 높이를 똑같이 맞춘다.
  2. **(기간)** 7일 / 28일 / 전체 **세 칸 전환 버튼** 하나로 모든 숫자가 같이 바뀜.
  3. **(강조)** 새 기록(첫 페스티벌 등)에만 색 배지 — 평범한 사건은 회색.
- 공개: 앱은 가입 필요(무료 등급 있음). 공개 화면 샘플은 적음.

#### ⑤ Spotify for Artists — 청중(Audience) 화면
- 링크: 데이터 읽는 법 https://artists.spotify.com/blog/how-to-read-your-spotify-for-artists-data · 발매 상세 화면 소개 https://artists.spotify.com/en/blog/release-details-page-and-audience-engagement-analytics
- 닮은 점: 한 아티스트의 숫자를 "청중 / 음악 / 상세" 탭으로 나눈다 — 우리 팀 상세의 탭 나누기와 같다.
- 빌려올 점:
  1. **(그래프)** 선 그래프 하나 + 마우스를 올리면 그날 숫자 — 그래프를 여러 개 늘어놓지 않는다.
  2. **(색)** 검정 바탕 + 초록 하나 — **강조색 하나만 쓰는 흑백 모드**의 좋은 예.
  3. **(구성)** '어디서 왔나(출처 비율)'를 가로 막대로 — 우리 '점수 근거 구성'을 원그래프 대신 한 줄 막대로.
- 공개: 블로그 화면 캡처는 공개. 앱은 본인 아티스트 계정만. (블로그 글이 2021년 것이라 지금 화면과 다를 수 있음)

#### ⑥ Kworb — 아티스트별 차트 기록
- 링크: https://kworb.net/ (예: 스포티파이 아티스트 목록 https://kworb.net/spotify/artists.html)
- 닮은 점: 순위표 그 자체. 꾸밈 없이 **글자와 숫자만으로** 수천 줄을 보여 준다.
- 빌려올 점:
  1. **(표)** 숫자는 고정폭 글꼴·오른쪽 정렬, 줄 간격 촘촘 — 우리 순위표 숫자 칸에 그대로.
  2. **(색)** 색은 "올랐다/내렸다"에만 — 나머지는 전부 검정.
  3. **(구조)** 페이지 하나 = 표 하나. 설명은 표 위 한 줄.
- 공개: 전부 공개, 가입 없음. (앞 조사 `dashboard_patterns.md` ⑤에도 있음)

#### ⑦ Resident Advisor(RA) — 공연장·아티스트·이벤트 페이지
- 링크: https://ra.co/ · 예: 아티스트 공연 일정 https://ra.co/dj/touchbase/tour-dates · 레이블 페이지 https://ra.co/labels/2526
- 닮은 점: **공연장(클럽) ↔ 아티스트 ↔ 이벤트**가 서로 링크로 이어진다 — 우리 '공연장/씬 네트워크'와 가장 비슷한 실제 서비스. 전자음악 씬 잡지라 글과 데이터가 섞여 있다.
- 빌려올 점:
  1. **(공연장 화면)** 공연장 페이지 = 이름·도시 → 다가오는 공연 → 지난 공연 목록. 지난 공연 줄마다 그날 나온 팀 이름이 링크 — 우리 공연장 화면을 이 순서로.
  2. **(글꼴)** 큰 굵은 제목 + 작은 회색 날짜, 흑백 위주 — 잡지 느낌을 주는 가장 쉬운 방법.
  3. **(꼬리표)** 'Local Artist' 같은 짧은 꼬리표 하나 — 우리 '갓 데뷔'·'참고' 배지와 같은 쓰임.
- 공개: 전부 공개(티켓 구매만 로그인).

#### ⑧ Discogs — 아티스트·크레딧 페이지
- 링크: https://www.discogs.com/ (아무 아티스트·음반 페이지)
- 닮은 점: 아티스트 ↔ 음반 ↔ 레이블 ↔ 참여자(크레딧)가 전부 링크로 이어진 **관계 데이터베이스**를 사람이 읽기 좋게 펼친다 — 우리 관계망을 '그림' 대신 '목록'으로 보여 줄 때의 답.
- 빌려올 점:
  1. **(팀 상세)** "함께한 사람/팀" 목록을 역할별(같은 무대·같은 레이블·같은 프로그램)로 묶어 접기 — 관계망 그래프 옆에 둘 목록.
  2. **(표)** 음반 목록 표: 연도·제목·레이블 세 칸이 기본, 나머지는 펼쳐야 보임.
  3. **(밀도)** 꾸밈 거의 없이 회색 칸 구분만 — 오래 써도 피곤하지 않은 화면.
- 공개: 전부 공개.

### 스카우팅 — 사람을 찾는 화면

#### ⑨ Baseball Savant — 선수 페이지(백분위 막대)
- 링크: 선수 예 https://baseballsavant.mlb.com/savant-player/elly-de-la-cruz-682829 · 백분위 순위표 https://baseballsavant.mlb.com/leaderboard/percentile-rankings · 비교 도구 https://baseballsavant.mlb.com/comparison-tool · 개편 소개 https://www.mlb.com/news/baseball-savant-statcast-player-pages-new-look
- 닮은 점: 선수 페이지 맨 위에 **항목마다 0~100 백분위 막대**를 늘어놓아 "어디가 강하고 약한지"를 한눈에 보여 준다. 우리 '점수 근거'(갈래·공연장 다양성·선정·매거진…)를 보여 주기에 가장 좋은 모양.
- 빌려올 점:
  1. **(점수 근거)** 신호마다 가로 막대 한 줄 + 끝에 동그라미 숫자(백분위). 강하면 진한 색, 약하면 옅은 색 — **원그래프·쌓은 막대보다 훨씬 읽기 쉽다.**
  2. **(비교)** 두 팀을 같은 막대로 나란히 놓는 비교 화면 — "왜 A가 B보다 위인가"에 바로 답한다.
  3. **(순위표)** 같은 막대를 순위표 칸 안에도 작게 넣기(표 + 미니 막대).
- 공개: 전부 공개, 가입 없음. **시안 A의 핵심 참고.**

#### ⑩ FBref — 스카우팅 리포트 · 비슷한 선수
- 링크: 리포트 설명 https://fbref.com/en/about/scouting-reports-explained · 출시 글 https://www.sports-reference.com/blog/2021/02/fbref-scouting-reports-and-similar-players-launched/
- 닮은 점: "같은 포지션 선수들 사이에서 몇 %인가"로 비교하고, 밑에 **비슷한 선수 10명** 표 + '비교' 링크. 우리 '같은 단계 팀과 비교'·'비슷한 선례 팀'과 같다.
- 빌려올 점:
  1. **(점수 근거)** "무엇과 비교한 백분위인지"를 표 위에 한 줄로 명시("최근 365일 · 같은 포지션") — 우리도 "첫 발매 2년 이내 팀 N개 중".
  2. **(팀 상세)** 맨 아래 '비슷한 팀 10' 표 + 팀마다 [비교] 버튼.
  3. **(표)** 회색 줄무늬 + 굵은 머리줄만 — 표 꾸밈의 최소치.
- 공개: 전부 공개.

#### ⑪ Hudl StatsBomb — 선수 영입(스카우팅) 플랫폼
- 링크: https://www.hudl.com/products/statsbomb/platform · 영입 활용 글 https://blogarchive.statsbomb.com/articles/soccer/using-statsbomb-iq-for-player-recruitment/ · 선수 유형 글 https://www.hudl.com/blog/modern-scouting-workflows-player-archetypes-statsbomb
- 닮은 점: 프로 구단 스카우트가 쓰는 **후보 찾기 → 비교 → 근거 영상** 도구. 우리 앱의 목적(신인 발굴)과 업무 흐름이 가장 닮았다.
- 빌려올 점:
  1. **(그래프)** 레이더(거미줄) 그래프로 두 선수 겹쳐 보기 — 우리는 신호 수가 적어 레이더보단 막대가 낫지만, '두 팀 겹쳐 보기' 아이디어는 쓸 만하다.
  2. **(근거 잇기)** 지표를 누르면 그 지표에 해당하는 장면(영상) 목록이 나옴 — 우리도 점수 근거 막대를 누르면 **그 근거가 된 공연·선정·기사 목록**이 펼쳐지게.
  3. **(유형)** 선수를 '유형(archetype)'으로 묶음 — 우리 팀을 "공연형 / 선정형 / 매거진형"으로 묶는 꼬리표.
- 공개: 소개 페이지·블로그만. 앱은 구단 계약.

#### ⑫ Transfermarkt — 선수 프로필
- 링크: https://www.transfermarkt.com/ (아무 선수 페이지 → '시장 가치' 그래프·'이적 기록' 표)
- 닮은 점: 선수 한 명의 **경력 타임라인(이적 기록)과 가치 변화 그래프**가 한 페이지에. 우리 팀 상세의 '활동 기록 + 점수 변화'와 같은 구성.
- 빌려올 점:
  1. **(그래프)** 계단식 가치 그래프 + 점마다 그때 소속 — 우리 '점수 변화' 그래프에 그때의 사건을 같이.
  2. **(표)** 이적 기록 표: 날짜 · 떠난 곳 → 간 곳 — 우리 '공연장 이동'(작은 곳 → 큰 무대) 표로 바꿔 쓰기 좋다.
  3. **(머리)** 사진 · 이름 · 소속 · 핵심 숫자 하나를 맨 위 띠에 고정.
- 공개: 전부 공개(광고 많음 — 광고 빼고 구조만 볼 것).

### 실무형 도구 — 촘촘하지만 조용한 화면

#### ⑬ Linear — 업무 관리 도구
- 링크: https://linear.app/ · 2026년 3월 개편 글 "A calmer interface" https://linear.app/now/behind-the-latest-design-refresh · 개편 변경 기록 https://linear.app/changelog/2026-03-12-ui-refresh · 2024 개편 글 https://linear.app/now/how-we-redesigned-the-linear-ui
- 닮은 점: 목록(이슈) → 누르면 상세. 정보가 촘촘한데 **차분하다**. 우리 순위표 → 팀 상세 흐름과 같다.
- 빌려올 점:
  1. **(배치)** 왼쪽 메뉴는 **본문보다 살짝 흐리게** 해서 본문이 먼저 보이게 — 2026 개편의 핵심.
  2. **(선)** 다크 모드에서 테두리를 **더 옅게**, 칸 구분을 덜 세게.
  3. **(조작)** 표에서 위아래 키로 줄 이동 · 엔터로 상세 · 단축키 안내를 구석에 작게.
- 공개: 소개·블로그 공개. 앱은 무료 가입으로 볼 수 있음.

#### ⑭ Vercel Geist — 디자인 규칙집(표·색·글꼴)
- 링크: 전체 https://vercel.com/geist · 표 https://vercel.com/geist/table · 색 https://vercel.com/geist/colors
- 닮은 점: 흰/검정 두 모드를 **같은 규칙으로** 만든 공개 디자인 규칙집. 우리 앱의 화이트/블랙 모드를 다듬을 때 그대로 따라 할 수 있다.
- 빌려올 점:
  1. **(색)** 회색을 단계별로 정해 두고 바탕·선·글자를 그 안에서만 고름 — 지금 우리는 회색이 여기저기 제각각.
  2. **(표)** 줄무늬 표 · 아주 많은 줄은 '더 보기'로 나눠 그림 — 표 규칙을 하나로.
  3. **(글꼴)** 숫자용 고정폭 글꼴을 쓰는 자리를 정해 둠.
- 공개: 전부 공개.

#### ⑮ Plausible — 웹 방문 통계(공개 실시간 대시보드)
- 링크: 실제로 돌아가는 공개 대시보드 https://plausible.io/plausible.io · saasframe 캡처 https://www.saasframe.io/examples/plausible-sites-dashboard
- 닮은 점: 화면 **한 장**에 큰 그래프 하나 + 아래 '상위 목록' 표 몇 개. 꾸밈이 거의 없는데 투박하지 않다. 우리 첫 화면(오늘 볼 것)에 딱 맞는 크기.
- 빌려올 점:
  1. **(첫 화면)** 맨 위 숫자 4~5개(누르면 아래 그래프가 그 숫자로 바뀜) — 숫자 카드와 그래프를 따로 두지 않는다.
  2. **(표)** 목록 줄 뒤에 **옅은 색 막대를 깔아** 크기를 표시(표 + 막대를 한 칸에) — 순위표·공연장 목록에 바로 쓸 수 있다.
  3. **(필터)** 표의 줄을 누르면 그게 필터가 되어 화면 전체가 좁혀짐(위에 꼬리표로 표시, ✕로 해제).
- 공개: 공개 데모 대시보드는 가입 없이 열림.

## 3. 시안 A / B / C — 우리 화면에 적용하면

### 지금 앱의 생김새 (비교 기준)
- 글꼴: 시스템 기본 고딕(애플 고딕·Noto Sans KR), 숫자는 고정폭.
- 색: 흰/검정 바탕 + **파란색 한 계열**(진한 파랑~옅은 하늘색 여러 단계로 점수 구성을 칠함). 이 파랑·회색 조합이 웹 개발 도구(Tailwind)의 기본 색과 같아서 **"어디서 본 듯한 AI 화면" 느낌의 큰 원인**이다.
- 모양: 모서리 4px, 알약 모양 배지 많음(약 19곳), 그림자 8곳.
- 화면: 오늘 · 후보 · 팀 상세(점수 근거·관계망·활동 기록) · 공연장/씬 · 검증(백테스트·성적표) · 관심 목록 등.

### 시안 A — 분석 도구형 (Baseball Savant · FBref · Chartmetric)

참고 링크
- https://baseballsavant.mlb.com/savant-player/elly-de-la-cruz-682829 (선수 페이지 맨 위 백분위 막대)
- https://baseballsavant.mlb.com/comparison-tool (두 명 비교)
- https://fbref.com/en/about/scouting-reports-explained (백분위 기준 명시 + 비슷한 선수)
- https://hmc.chartmetric.com/chartmetric-artist-overview-page/ (아티스트 개요 화면)

우리 화면에서 바뀌는 것
- **후보 순위표**: 점수 칸 옆에 신호별 **미니 백분위 막대 4~6개**(갈래·공연장 다양성·선정·매거진…). 숫자 칸 고정폭·오른쪽 정렬. 한 화면에 30~40줄.
- **팀 상세**: 맨 위 = 이름·단계 꼬리표·점수 / 바로 밑 = **신호별 백분위 막대 목록**("첫 발매 2년 이내 팀 N개 중")이 핵심. 막대를 누르면 근거(공연·선정·기사) 목록이 펼쳐짐. 맨 아래 '비슷한 팀 10 + [비교]'.
- **공연장/씬**: 공연장마다 '거쳐 간 팀이 나중에 얼마나 컸나'를 백분위로 정렬하는 표.
- **검증**: 성적표를 '선수 기록표'처럼 — 시기별 줄, 맞춘 비율 칸에 막대.
- 색: 강함=진한 한 색, 약함=옅은 회색(Savant의 빨강/파랑 두 색을 그대로 쓰지 않고 한쪽 색만).
- 장점: "왜 이 팀이 위인가"가 가장 분명함. 스포츠 기록 사이트 느낌이라 AI틱하지 않다.
- 단점: 숫자가 많아 처음 보는 사람에겐 빽빽함. 백분위를 계산할 기준 묶음(같은 단계 팀)을 정해야 함 → **데이터 쪽 작업이 조금 필요**(점수 SQL에 백분위 열 추가).

### 시안 B — 조용한 업무 도구형 (Linear · Vercel Geist · Plausible)

참고 링크
- https://linear.app/now/behind-the-latest-design-refresh (차분한 화면으로 바꾼 이유·방법)
- https://vercel.com/geist/colors · https://vercel.com/geist/table (흑백 두 모드 색 규칙·표 규칙)
- https://plausible.io/plausible.io (꾸밈 없는 한 장 대시보드)
- https://www.saasui.design/pattern/table (실제 제품 표 모음)

우리 화면에서 바뀌는 것
- **전체**: 회색 단계를 다시 정하고 바탕·선·글자를 그 안에서만. 강조색은 **하나**(파랑 여러 단계를 버리고, 예: 진한 주황 또는 초록 한 색). 알약 배지를 네모 꼬리표로, 그림자 없앰, 왼쪽 메뉴는 본문보다 흐리게.
- **후보 순위표**: 줄 뒤에 옅은 막대를 깔아 점수 크기 표시(Plausible식). 줄을 누르면 **오른쪽에 팀 상세가 반쯤 열림**(페이지 이동 없이), 위아래 키로 다음 팀.
- **팀 상세**: 탭을 줄이고 한 줄기로 — 요약 3줄 → 점수 근거 → 활동 기록 → 관계망. 관계망 그래프는 회색 선 + 강조색 노드만.
- **공연장/씬**: 표 + 표 줄을 누르면 필터가 되는 방식(위에 '공연장: ○○ ✕' 꼬리표).
- **검증**: 숫자 4개 + 선 그래프 하나 + 표. 지금보다 칸 수를 줄임.
- 장점: 지금 구조를 거의 그대로 둔 채 **색·선·간격 정리만으로** 투박함이 빨리 사라짐. 매일 쓰기 편함. 작업이 가장 작다.
- 단점: 잘못하면 '흔한 SaaS 템플릿'처럼 보임 → 강조색 선택과 글꼴(C의 제목 글꼴 일부 빌리기)로 개성을 줘야 함.

### 시안 C — 에디토리얼(잡지)형 (Resident Advisor · The Pudding · Kworb)

참고 링크
- https://ra.co/ (공연장·아티스트·이벤트가 이어진 음악 잡지)
- https://ra.co/dj/touchbase/tour-dates (아티스트 공연 일정 목록)
- https://pudding.cool/2023/10/genre/ (음악 데이터를 글과 그림으로 풀어낸 기사)
- https://kworb.net/ (꾸밈 없는 글자·숫자 표)

우리 화면에서 바뀌는 것
- **전체**: 제목에 **명조(세리프) 또는 개성 있는 굵은 제목용 글꼴**(무료 한글 글꼴 중에서), 본문은 지금 고딕. 흑백 위주, 아티스트 사진을 크게. 여백 넓게.
- **첫 화면**: '이번 주 눈여겨볼 팀 3'을 **기사 제목처럼** 한 문장 + 사진, 그 아래 순위표.
- **팀 상세**: 맨 위 사진·이름을 크게, 점수 근거를 **문장으로 먼저**("최근 6개월 공연장 7곳, 그중 3곳은 처음 서는 무대"), 숫자는 그 밑. 활동 기록은 날짜를 왼쪽 큰 글씨로 한 **연대기**.
- **공연장/씬**: RA처럼 공연장 페이지 = 소개 한 줄 → 다가오는 공연 → 지난 공연(그날 팀들 링크). 씬 네트워크 그림은 '지도'처럼 크게 한 장.
- **검증**: 성적표를 짧은 글 + 그림 한 장(The Pudding식)으로 — "작년 이맘때 골랐던 20팀 중 몇 팀이 페스티벌에 섰다".
- 장점: 가장 개성 있고 AI틱함과 거리가 멀다. 처음 보는 사람·면접관에게 보여 주기 좋다.
- 단점: 매일 많은 팀을 빨리 훑기엔 느림. 글꼴·사진·문장 자동 생성까지 손이 많이 가서 **작업이 가장 크다.** 사진이 없는 팀이 많으면 빈 곳이 티 난다.

### 섞어 쓰는 안 (제안)
- **B를 바탕**(색·선·간격·목록↔상세 반쯤 열기) + **A의 백분위 막대는 팀 상세 점수 근거에만** + **C의 제목 글꼴과 '문장 먼저'는 첫 화면·주간 브리핑에만**.
- 이유: 매일 쓰는 화면(순위표)은 빨라야 하고, 설득하는 화면(팀 상세·브리핑)은 근거와 이야기가 필요하다. 한 번에 다 바꾸지 않고 **B(색·선) → A(막대) → C(첫 화면)** 순서로 나눠 하면 단계마다 결과를 보며 고를 수 있다.

## 4. AI틱함을 피하는 점검표 (어느 시안이든)

| 피할 것 | 대신 |
|---|---|
| 파랑~하늘색 여러 단계로 칠하기(웹 도구 기본색) | 강조색 하나 + 회색 단계. 색은 '의미'(갈래 4색, 오름/내림)에만 |
| 보라·분홍 그라데이션, 유리(반투명) 효과 | 단색 바탕 |
| 큰 둥근 카드를 격자로 잔뜩 | 표와 목록 중심, 카드는 맨 위 요약에만 |
| 알약 모양 배지 여러 개 | 네모 꼬리표 하나, 꼭 필요한 곳만 |
| 이모지·장식 아이콘 | 출처 로고 또는 글자 |
| 원그래프·도넛 | 가로 막대 한 줄 |
| 모든 숫자에 '큰 숫자 카드' | 숫자는 표 안에, 정말 중요한 1~2개만 크게 |
| 그림자 | 옅은 선 한 줄 |
