# 무대·라이브 세션 채널 출연 — 나중 정답을 미리 알려 주나

_자동 생성: `.venv/bin/python scripts/live_sessions.py` (계산만 — config·계산식·랩 데이터는 바꾸지 않음)_

## 1. 지금 상태

- 무대 영상(`docs/lab/data/videos.csv`, kind=stage)은 **지금 signals에 들어가지 않습니다.** 앱에서 팀 상세의 영상으로만 보입니다. 그래서 '출연'을 **임시 큐레이션 신호**(출처 `video_<채널>`, 날짜 = 업로드일)로 만들어 메모리 안에서만 더했습니다 — 971행(같은 팀·채널·날짜는 한 줄).
- 업로드일은 실제 출연·녹화일보다 늦을 수 있어, '정답보다 먼저 짚었다'를 덜 세는(보수적인) 쪽입니다.
- 같은 집안: EBS 스페이스 공감 ↔ EBS 헬로루키(월간·올해의). 정답 발표 전에 스페이스 공감에 나온 팀의 헬로루키 정답 15건을 적중에서 뺐습니다.
- ⚠️ **모든 무대 영상이 2025-10 이후 업로드입니다**(수집기가 최근 업로드만 훑음). 점수 검증 기준일(2023-01-01 ~ 2025-07-01) 전에 영상 신호가 **0건**이라, 6개 기준일 교차 검증에는 영향이 0입니다. 더해도 숫자가 그대로인 것은 '효과 없음'이 아니라 '잴 수 없음'입니다.

## 5. 요청 (코디네이터)

1. `config/source_roles.json` signals에 영상 출처를 **pending**으로 등록할지 결정 — 지금은 signals에 안 들어가므로, 넣으려면 `export_lab_data`가 무대 영상을 `큐레이션:video_<채널>` 신호로 내보내야 합니다(같은 집안 짝 `큐레이션:video_ebs_space` ↔ hello_rookie·hello_rookie_year 추가).
2. **과거 업로드 백필**: 수집기의 채널별 `max_pages`를 늘려 2021~2025 업로드를 모으면(업로드 목록 50개당 API 1단위라 비용이 작음) 6개 기준일로 바로 성적을 잴 수 있습니다. 이번 평가에서 가장 큰 한계입니다.
3. 그 전까지는 점수에 넣지 않고(features.sql 변경 없음), 팀 상세의 '무대 영상' 정보로만 씁니다.

## 6. 한계

- 영상은 우리 팀 목록의 이름과 맞는 것만 모았습니다(수집기가 우리 팀 이름으로 제목을 맞춤). 그래서 우리 데이터에 없는 팀의 출연은 처음부터 빠집니다.
- 업로드일 ≠ 출연일, 한 팀이 여러 번 출연하면 신호도 여러 번입니다(출처 성적표는 팀 단위라 영향 작음).
- KBS Kpop은 업로드가 아주 많은 채널이라 일부(최근 쪽)만 훑었습니다.
